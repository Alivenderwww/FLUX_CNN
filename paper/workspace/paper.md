# 摘要 {#摘要 .标题-居中}

面向qHD/1080p高分辨率单批次实时视频流的端侧推理场景，卷积神经网络加速器需同时满足单批次流式输入、毫秒级单帧延迟与瓦级功耗等多重约束。本文围绕该场景完成一款面向专用集成电路平台的卷积加速器FLUX_CNN的完整设计、实现与多阶段验证。加速器以核内寄存器配置加核间任务描述符链表的软硬协同双层调度为核心，数据通路采用16×16 INT8乘加阵列与三级寄存器堆，同时实施输入通道广播、权重静止、激活值滑窗行复用与输出部分和累加四层数据流复用策略；加速核内置残差通路，shortcut分支在输出特征缓冲内原地累加，避免残差中间结果落回片外DDR。针对小通道与大步长层的PE低利用率，编译器侧提出Y维折叠与空间到深度两种重映射方法；配套构建覆盖PyTorch模型解析与量化、图级调度与层间融合、代码生成与任务描述符编排的端到端工具链；多核扩展层采用W维切片调度，在不改动单核RTL的前提下提供$N = 1, 2, 4$配置。验证采用三阶段平台形成完整闭环：阶段一在Xilinx Kintex-7 XC7K325T平台对四核配置完成布局布线，推荐工作频率135.86 MHz、片上功耗1.925 W、峰值算力278 GOP/s、能效144 GOP/W；阶段二在VD100开发板（Versal AI Edge XCVE2302）上完成三核SoC集成与板级烧录，配套上位机Demo GUI实现端到端推理演示；阶段三基于OpenLane2在Skywater 130 nm工艺下完成单核版图实现并折算至45 nm，4核估计15.4 mm² / 0.54 W、850 MHz下峰值算力1.74 TOP/s、能效3.2 TOP/W。ResNet-11整网在135.86 MHz下达783 FPS，超出qHD视频流30 FPS实时基线约26倍。本文工作为端侧卷积加速器提供一套覆盖硬件、编译器与多阶段验证的自洽实现范式。

# Abstract {#abstract .标题-居中-英文}

For qHD/1080p single-batch edge inference, CNN accelerators must satisfy streaming input, millisecond latency, and watt-level power constraints. This work designs, implements, and verifies FLUX_CNN, a CNN accelerator for ASIC platforms. The accelerator uses a two-tier scheduling architecture combining intra-core register configuration with inter-core task descriptor chains; its data path employs a 16×16 INT8 MAC array with three-level register files and four-layer dataflow reuse (input channel broadcasting, weight stationary, activation sliding-window row reuse, and output partial sum accumulation); a residual path performs in-place accumulation in the output feature buffer to avoid DDR write-back. Two compiler-side remapping methods—Y-dimension folding and space-to-depth—address low PE utilization in small-channel or large-stride layers, supported by an end-to-end PyTorch toolchain. The multi-core extension uses W-dimension slicing, providing $N = 1, 2, 4$ configurations without RTL changes. Three-stage verification forms a closed loop: Stage 1 places and routes the four-core design on Xilinx Kintex-7 XC7K325T, reaching 135.86 MHz, 1.925 W, 278 GOP/s, and 144 GOP/W; Stage 2 integrates a three-core SoC on the VD100 board (Versal AI Edge XCVE2302) with a host demo GUI; Stage 3 implements a single-core layout in Skywater 130 nm via OpenLane2 and scales to 45 nm, with four cores estimated at 15.4 mm² / 0.54 W, 1.74 TOP/s, and 3.2 TOP/W at 850 MHz. ResNet-11 reaches 783 FPS at 135.86 MHz, 26× the qHD 30 FPS real-time baseline. This work delivers a self-consistent paradigm for edge-side CNN accelerators covering hardware, compiler, and verification.

**Key Words: Convolutional Neural Network Accelerator; Streaming Computation; Hardware-Software Co-Scheduling; Dataflow Reuse**

#  文献综述

##  研究背景与意义

随着人工智能技术在边缘端的广泛应用，越来越多的场景要求将卷积神经网络（Convolutional
Neural
Network，CNN）等深度学习模型直接部署于资源受限的终端设备上。智慧城市的视频监控^[1]^、工业视觉缺陷检测^[2]^、消费电子中的手势识别与关键词唤醒^[3]^、自动驾驶辅助感知^[4]^等典型场景，均呈现"高带宽数据流---边缘处理---低时延响应"的流式计算特征：城市监控场景中，部署于路口的高清摄像设备需对每秒数十帧的高清视频流进行实时目标检测、车牌识别与行为分析，推理延迟普遍要求控制在50
ms以内；工业视觉缺陷检测场景往往需要对产线上行进的工件表面进行缺陷分割，且不允许出现帧丢失；消费电子中的手势识别与关键词唤醒则要求处理设备的低功耗；自动驾驶辅助感知更是对端到端延迟和安全提出严苛要求。与云端推理相比，端侧部署能够显著降低数据上传带宽、保障用户隐私，提供实时响应，已成为人工智能落地的重要路径。

端侧场景普遍承载ResNet、MobileNet、YOLO等多种网络的并行部署需求，对加速器在保持高能效的同时提供模型快速适配能力提出综合要求。主流CNN模型的参数量与单次推理计算量普遍在$10^{7}$至$10^{9}$次乘加（Multiply-Accumulate，MAC）量级^[5]^；而端侧设备的供电功耗通常限制在数瓦乃至数百毫瓦以内，片上存储容量往往仅为数
MB。将通用处理器（CPU）或图形处理器（GPU）直接移植到端侧推理面临算力不足或功耗过大的两难困境^[6]^：CPU顺序指令流模型难以在功耗限制内提供实时吞吐；GPU大规模SIMT架构与高速显存功耗占比过大，能效比显著低于专用加速硬件。商用端侧NPU如Google
Edge TPU、Intel Movidius、Apple Neural
Engine虽证明了硬件定制加速的工程可行性，但其架构细节与编译栈通常闭源发布，且单一通用产品难以覆盖端侧应用碎片化的算子组合与功耗约束差异^[6]^。由此，面向特定端侧流式场景、以可复现可演进为目标的卷积加速器定制化设计，仍是当前硬件架构研究的主要热点之一^[7-10]^。

CNN加速器设计的核心挑战在于"计算---访存"不平衡。卷积运算本质上是规则的多维张量乘累加，其算术强度对数据复用策略极度敏感：输入特征图沿空间维度被多个输出位置共享，卷积核在批量与空间维度上被反复使用，输出部分和则需在通道方向累加聚合。若数据复用策略不当，片外动态随机存取存储器（Dynamic
Random-Access
Memory，DRAM）的访问能耗将吞噬大部分能量预算。早期加速器采用全硬化卷积状态机，在小规模模型上可取得高能效，但面对任意$K \times K$卷积核、可变步长（Stride）、多分支残差等现代网络结构时硬件逻辑复杂度急剧上升^[8]^。软硬协同设计由此成为近年来的主流设计范式：将空间迭代、通道切片、层间依赖等调度决策交由软件完成，硬件仅负责执行简单、规则、可流水的算子^[9,10]^，二者通过紧凑的配置接口或宏粒度指令耦合。

本论文在上述背景下，以端侧流式CNN推理为目标场景，设计并实现了一款软硬协同分层调度的卷积加速器FLUX_CNN。工程意义在于通过分层调度架构兼顾灵活性与高能效，为端侧定制化卷积加速器提供一种可参考的硬件实现范式；学术意义在于通过模块化设计实践为该领域提供可复现、可扩展的研究平台。

### 1.2 国内外相关研究工作进展

###  端侧卷积神经网络硬件加速器架构研究进展

CNN
专用硬件加速器研究可追溯至2014年寒武纪团队提出的DianNao系列^[11]^，其神经运算单元（Neural
Functional
Unit，NFU）配合输入缓冲、权重缓冲、输出缓冲三缓冲结构奠定了后续端侧加速器的基本范式。Google于2017年发布的TPU^[12]^将脉动阵列（Systolic
Array）引入大规模矩阵乘法加速；其粗粒度指令集思路对后续端侧加速器影响深远------硬件支持少量宏粒度指令即可表达完整推理流程，避免端侧场景下指令缓冲与取指开销对功耗的侵蚀。

麻省理工学院Chen等人提出的Eyeriss架构^[13]^在数据流层面做出奠基性贡献，系统比较了权重静止、输出静止、行静止等多种数据流策略并选择RS方案以最大化卷积核、部分和、输入激活三者的协同复用，建立了数据流策略与片上能耗之间的定量映射，成为学术界CNN加速器的重要标杆。Eyeriss
v2^[14]^针对移动端稀疏网络进一步引入灵活的分层mesh互联，使单一硬件能在不同层间动态切换数据复用模式。Parashar等人的SCNN^[15]^通过压缩稀疏权重与跳零机制降低冗余计算；Horowitz的经典能耗分析^[16]^指出片外DRAM访问能耗高出片内寄存器访问约三个数量级，为后续"数据尽量留在片内"的设计思路提供理论依据。Du等人的ShiDianNao^[17]^通过近传感器架构把数据通路收缩在传感器与计算阵列之间的短链路内，与流式计算场景的能效诉求一脉相承。

2020年后，开源与标准化成为该领域重要趋势。NVIDIA的NVDLA^[18]^作为开源参考设计，采用CDMA-CBUF-CSC-CMAC-CACC-SDP-PDP六级独立模块流水线结构，模块间通过握手与中间缓冲传递数据，便于在不同SoC中按需裁剪。FPGA加速器方向，Genc等人的开源框架Gemmini^[19]^为DNN架构系统评估提供完整SoC集成方案；Yu等人的OPU^[20]^通过CNN专用指令集使多种模型共享同一硬件部署、无需针对每个模型重综合；Zhang等人的DNNBuilder^[21]^验证了从高层网络描述直接生成FPGA比特流的端到端编译流程可行性。Aung等人的DeepFire2^[22]^在多芯片FPGA上达到600
MHz运行频率；Kim等人针对移动FPGA的可重构目标检测加速器^[23]^通过RTL级优化在能效、资源利用率与吞吐率三维度同步提升$15\%\sim 58\%$。国内方面，Zhao等人的紧凑查找表乘法器结构^[24]^结合4-bit量化压缩模型体积。Mohaidat等人最新综述^[25]^指出端侧$50\sim 500 GOPS$、$1\sim 3 W$功耗区间已成为该领域学术界共识。

###  软硬件协同调度与流式计算加速研究进展

软硬协同调度的思想可追溯至通用计算领域的VLIW（Very Long Instruction
Word）架构。Moreau等人的VTA（Versatile Tensor
Accelerator）^[26]^是将VLIW范式引入深度学习加速器的标志性工作：通过张量指令（Tensor
Instruction）解耦硬件流水与算法迭代，硬件内部维护计算、加载、存储三组并发执行单元；同时建立TVM软件栈与硬件之间的桥梁。然而张量指令集仍保留取指、译码、依赖跟踪等通用处理器开销；Reuther等人的综述^[16]^亦指出端侧静态卷积场景下指令控制路径的动态功耗不可忽略。该类场景中网络拓扑在推理阶段固定、层内不存在运行时分支，完整指令流的控制灵活性对该场景收益有限^[6]^。

层间流式融合（Layer
Fusion）是另一条重要优化路线。Alwani等人的Fused-Layer
CNN^[28]^首次实现跨多层流水推理：上层产出若干行输出即可触发下层计算，片上缓存需求从$O_{H \times W}$降至$O_{K \times W}$。Shen等人的Escher^[29]^、Xiao等人的FPGA层融合工作^[30]^进一步将该思路工程化，在特定网络上达到2\~5倍能效提升。层融合的主要难点在于不同层K、stride、padding各异，硬化状态机难以适配；融合层数过深还会导致片上缓冲与控制状态空间膨胀。如何在硬件侧提供规则的缓冲与同步原语、把融合策略交由软件动态决定，是该方向尚未形成统一接口的工程难点。

数据流可重构（Dataflow
Reconfigurability）方面，Kwon等人的MAERI^[31]^通过可重构mesh互联支持多种数据流动态切换；Qin等人的SIGMA^[32]^将该思路扩展至不规则稀疏矩阵乘法。这类工作代表"软件指定数据流"的技术路径，主要代价是互联面积与控制复杂度------在端侧单层卷积场景下最优数据流策略相对固定，柔性互联的边际收益递减；灵活性需求更应迁移到核间互联与任务编排层面。

多核扩展方面，NVIDIA与MIT合作的Simba^[27]^采用36芯片多核mesh架构，揭示了多核扩展中数据路由与负载均衡的工程难点。Tan等人的NN-Baton^[33]^针对分布式NPU从算子、张量、子张量三层粒度建立任务搜索空间；Wang等人的分布式CNN推理框架^[34]^在多FPGA平台上实现跨层流水推理。多核调度的核心难点在于：层间张量形状变化较大时，简单同步广播导致显著等待，如何在静态调度与动态反馈之间取得平衡仍是开放问题。

新大模型时代Vision
Transformer（ViT）^[35]^的兴起对CNN加速器架构亦提出新挑战。Sun等人的VAQF^[36]^、You等人的ViTCoD^[37]^等ViT专用加速器通过算法硬件协同、极化注意力图等方式降低计算复杂度。尽管ViT的自注意力与CNN的滑窗卷积访存特征差异较大，但二者在张量乘累加这一基础算子层面仍有共性。

综合上述分析可见，端侧CNN加速器发展呈现三条明显趋势：

其一，从硬化控制向软硬协同调度演化；

其二，从层内优化向跨层流式融合扩展；

其三，从单核高性能向多核高能效延伸。

然而以1080p单batch实时处理为核心约束的端侧场景下，现有工作可按局限性质分为四类：

第一类，**核内控制开销冗余**。以VTA^[26]^、Gemmini^[19]^、NVDLA^[18]^为代表的开源参考设计沿用张量指令流或多模块独立FSM的控制；在端侧静态卷积场景下，推理阶段网络拓扑与卷积参数均已固定，运行时取指、译码、依赖跟踪等通用控制开销对该场景收益有限，反而成为不可忽略的功耗与面积负担。

第二类，**单batch高分辨率流式接口缺失**。以TPU^[38]^、Simba^[27]^为代表的数据中心方案面向大batch吞吐优化，以DianNao^[11]^、Eyeriss^[13,14]^、SCNN^[15]^为代表的学术研究主要在$224 \times 224$量级图像上验证；在1080p单batch流式输入下，整图无法纳入片上IFB，且现有架构缺少触发下层计算的硬件接口。Stream^[39]^、DeepFrack^[40]^、ZigZag^[41]^等框架将层融合自动化推进至算子融合，但仍缺少流式融合的硬件接口；多核加速器的数据路由与同步机制仍是个案设计，缺少可在不同网络与不同核数下复用的统一调度。

第三类，**PE利用率随层形状骤降**。固定阵列在小 $C_{in}$、大stride、任意
$K 卷积层$上利用率显著低于峰值；MAERI^[31]^、SIGMA^[32]^等可重构数据流方案通过柔性互联部分缓解，但引入显著的互联与控制开销，对功耗与面积并不友好。固定阵列方案在端侧场景尚缺少系统化的实践。

第四类，**多模型快速适配的编译链能力**。端侧场景普遍需求多种网络的并行部署，OPU^[20]^、DNNBuilder^[21]^等展示了编译流程的工程可行性，但工具链覆盖范围仍以各家定制设计为主，缺少紧密协同的端到端部署。

##  本论文的主要研究内容

针对上述研究空间，本论文设计并实现卷积加速器FLUX_CNN，从核内控制、多核调度、利用率优化、软件部署与多阶段验证五个方向展开工作：

第一，提出**核内寄存器配置 + 核间描述符链表的双层调度架构**。核内采用配置寄存器 + 6 层嵌套自循环 FSM 完成单层全部调度，推理阶段无运行时取指、译码与依赖开销；核间采用 Task Descriptor 链表，编排多层与多核的数据路由；针对残差网络结构，加速核内置残差通路，shortcut 分支的 1×1 卷积输出与主路径 3×3 卷积输出在输出特征缓冲内进行原地累加，避免残差中间结果落回片外 DDR。

第二，提出**单 batch 高分辨率行级流式 + 多核 W 维切片调度机制**。单核内上层产出若干行 OFM 即触发下层计算，将片上缓冲需求从 ${O}_{H \times W}$ 降至 ${O}_{K \times W}$；多核之间采用 W 维切片，每核处理一段图像宽度子图加重叠列，相邻核之间通过跨核直送把上一层 OFM 直接写入下一核 IFB，避免经过外部 DDR 中转；多核同步通过描述符链表完成，不依赖中央调度器，多核扩展时单核 RTL 无需改动。

第三，提出**多维度数据复用 + Ky-fold / S2D 编译器 PE 重映射**。硬件侧建立 $16 \times 16$ INT8 MAC 阵列与三级寄存器堆数据通路，采用输入通道广播、权重静止、激活值滑窗行复用与输出部分和累加四层数据流复用策略，支持任意 $K \times K$ 卷积核、任意步长、任意 $C_{in}/C_{out}$ 切片，在固定阵列规模下覆盖典型端侧 CNN 模型的全部卷积层形状。编译器侧进一步引入 Y 维折叠（Ky-fold）与空间到深度（Space-to-Depth，S2D）两种重映射方法，使 $C_{in} < 16$ 的层与 $\text{stride} > 1$ 的层在不改硬件接口的前提下填满处理单元并行计算。

第四，设计**端到端编译器工具链**。面向 PyTorch / TensorFlow 训练模型，构建前端算子解析与量化、中端图级调度与层间融合、后端代码生成与 Task Descriptor 编排的端到端部署链路。前端支持 Conv2D、BatchNorm、ReLU、Pooling、Residual Add 等典型 CNN 算子的适配；中端负责多层网络的层间融合、算子融合、核间任务切分与层优化策略决策；后端预算各地址步进、分块参数与 $C_{in}/C_{out}$ 切片策略，产出各核的寄存器配置与描述符链表。

第五，完成**三阶段平台实现验证**。阶段一在 Xilinx Kintex-7 XC7K325T 上对 4 核 INT8 SIMD 配置完成布局布线，推荐工作频率 135.86 MHz、片上功耗 1.925 W、DSP48E1 利用率 99.0%；阶段二在 VD100 开发板（Versal AI Edge XCVE2302）完成三核 SoC 集成烧录，配套上位机 Demo GUI 通过 PCIe 实现端到端推理演示；阶段三基于 OpenLane2 在 Skywater 130 nm 工艺下完成单核 `core_top` 版图实现至 post-CTS 阶段，单核总单元面积 31.96 mm²（其中 96 块 SRAM 宏占 27.32 mm²、标准单元 4.65 mm²），功耗 1.045 W；按 Stillmaker 与 Baas[44] 工艺缩放公式折算至 45 nm 节点，单核单元面积 3.84 mm²、功耗 0.136 W，4 核估计 15.4 mm² / 0.54 W。三阶段验证形成覆盖 FPGA 综合可行性、SoC 集成可运行性与 ASIC 工艺指标估算的完整链路。FPGA 平台配套提出 DSP 跨列复用映射方案，利用 DSP48E1 位宽冗余将两个 INT8 乘法合并至单个 DSP 块，使 $16 \times 16$ 阵列乘法器全部由 DSP 块承担。

#  理论基础

##  引言

卷积神经网络作为端侧视觉计算的主流模型，其加速器设计需要综合权衡算法层面的计算特征与硬件层面的资源约束。本章介绍CNN加速器设计所依赖的理论基础。

##  卷积神经网络基础

###  卷积层

卷积层是卷积神经网络中承担特征提取的核心层，其计算量通常占整个网络的$90\%$以上^[5]^，因此卷积计算的优化与加速是硬件加速器设计的重中之重。卷积运算的基本思路是用一个$K \times K$的卷积核在输入特征图上逐点滑动，将卷积核覆盖区域的输入与对应权重逐元素相乘并累加，最终得到输出特征图上的一个像素值。

![[]{#_Ref229495878 .anchor}图2.1
卷积计算示意图](.docx-media/media/image3.png){alt="P356#yIS1"
width="3.061349518810149in" height="1.1591447944006998in"}

如图2.1所示卷积计算原理。以$3 \times 3$卷积核为例，单通道情形下的卷积计算公式如下$公式(2.1)$：

$$\begin{array}{r}
Y(i,j) = \sum_{u = 0}^{K - 1}{\sum_{v = 0}^{K - 1}{a(i + u,\, j + v)}} \cdot w(u,v) + b
\end{array}$$

其中$Y$为输出特征图，$a$为当前滑窗下的输入特征图数据，$w$为与$a$对应的权重数据，$b$为偏置项。卷积核在滑动过程中权重保持不变，达到了权重共享的效果，使得参数量相对全连接层显著降低，这一性质既缓解了网络训练中的过拟合问题，也减少了硬件实现时的权重搬运开销，提高了计算效率。

实际网络中的卷积层往往涉及多通道输入与多通道输出。设输入通道数为$C_{in}$，输出通道数为$C_{out}$，则多通道卷积可表示为：

$$\begin{array}{r}
Y_{c_{out}}(i,j) = \sum_{c = 0}^{C_{in} - 1}{\sum_{u = 0}^{K - 1}{\sum_{v = 0}^{K - 1}{a_{c}(i + u,\, j + v)}}} \cdot w_{c_{out},c}(u,v) + b_{c_{out}}
\end{array}$$

其中$C_{in}$为输入通道序号，$C_{out}$为输出通道序号。从公式可以看出，多通道卷积的输出由所有输入通道在该位置的卷积结果求和并加偏置得到。在工程实践中，输入输出通道数往往达到64、128、256甚至更多，单层卷积所需的乘加运算量可达数百万至数亿次。因此，必须对通道维度切片，按片分批送入有限规模的MAC阵列计算，再在累加器中汇总，才能得到完整的输出特征图。

卷积层的另外两个重要参数是步长（stride）和填充（padding）。步长决定卷积核在输入特征图上的滑动间隔，步长为1时输出特征图与输入空间分辨率近似一致，步长为2时输出空间分辨率减半，常用于在网络中段实现下采样。填充则在输入特征图的边界外补零，以控制输出特征图的尺寸边界并保证边缘像素被卷积核充分覆盖。给定输入尺寸$H_{in}$、$W_{in}$、卷积核尺寸$K$、步长$s$、填充$p$，输出特征图尺寸为：

$$\begin{array}{r}
H_{out} = \left\lfloor \frac{H_{in} + 2p - K}{s} \right\rfloor + 1,\ \ W_{out} = \left\lfloor \frac{W_{in} + 2p - K}{s} \right\rfloor + 1
\end{array}$$

不同尺寸的卷积核可提取不同尺度的局部特征，$3 \times 3$、$5 \times 5$、$7 \times 7$是端侧CNN模型中最常用的三种卷积核尺寸。

###  池化层

池化层的主要功能是对卷积层输出的特征图进行下采样，以逐步压缩空间分辨率、减少后续卷积层的计算量并增大有效感受野。常见的池化尺寸为$2 \times 2，步长$为2，经过一次池化后特征图的高度和宽度各减为原来的一半，总像素数变为原来的四分之一。常用的池化方式有最大值池化（Max
Pooling）和平均值池化（Average
Pooling）两种。最大值池化与平均值池化的特征保留能力相近，但最大值池化只需比较运算，省去了平均值池化所需的加法和除法，因此在硬件实现中更为常用。在数据通路上，池化通常复用与卷积相同的行缓存与窗口生成逻辑，仅将乘加器替换为比较树或加法树，实现简单。

###  全连接层

全连接层常出现在分类网络的尾端，用于将卷积层提取的高维特征向量映射到类别分数。全连接层中每一个输出神经元都与所有输入神经元相连，其计算公式为：

$$\begin{array}{r}
y_{j} = \sum_{i = 0}^{N - 1}w_{i,j} \cdot x_{i} + b_{j}
\end{array}$$

其中$x_{i}$为全连接层的第$i$个输入神经元，$w_{i,j}$为输入$i$到输出$j$的连接权重，$b_{j}$为输出$j$的偏置项，𝑁$$为输入神经元数量。从计算结构上看，全连接层是$\ 1 \times 1$卷积的一种特例，可视作输入特征图尺寸等价为$\ 1 \times 1$、通道数为$\ N$、输出通道数为类别数的卷积层。因此，加速卷积层所采用的乘加阵列与数据通路同样可以复用于全连接层的计算，只需在地址生成器中将空间维度循环等价为单点循环即可。

##  数据流分类与硬件复用策略

卷积神经网络中存在大量的数据复用机会：同一卷积核在输入特征图上滑动时权重被反复使用、相邻输出位置共享部分输入像素、同一输入通道在不同输出通道间被广播。如何在有限的片上存储与片上互连约束下尽量挖掘这些复用机会，是硬件加速器架构设计的核心议题。Eyeriss^[13]^将卷积层的硬件数据流系统归纳为三种典型类型，分别对应图2.2不同复用对象与片上存储模式。

![[]{#_Ref229997731 .anchor}图2.2
数据流对比示意图](.docx-media/media/image4.emf){width="5.104046369203849in"
height="2.3315944881889763in"}

权重静止（Weight
Stationary，WS）：卷积核权重预先加载到MAC阵列内本地寄存器并保持不变，由输入激活值流动完成乘加；权重片外访问次数最少，代表实现包括
NVDLA[18]；主要不足在于卷积核小而$C_{out}$多时权重寄存器利用率偏低。

输出静止（Output
Stationary，OS）：输出像素或部分和固定在PE内本地寄存器，权重与激活值同时流入完成累加更新；部分和完全本地化避免了中间结果跨PE搬运，代表实现如ShiDianNao^[17]^等；主要不足在于权重与激活值都需流动，片上带宽压力相对较大。

行静止（Row
Stationary，RS）：由Eyeriss^[13]^提出，将卷积运算按"行权重、行输入、行部分和"的最小卷积单元映射到单个PE上，多个PE通过纵向、横向、对角线三种方向的数据传递组合出完整的二维卷积。该方案同时复用权重、输入、部分和，在卷积核尺寸、特征图尺寸变化时仍能保持较高PE利用率；主要代价是PE间局部互连复杂、编译器循环映射要求严苛。

三种数据流并非互斥。当目标场景以中小卷积核、规则形状、固定网络拓扑为主时，权重静止能在低控制复杂度下取得良好能效；当需要在多种卷积形状间灵活切换且片上互连预算充裕时，行静止可提供更高平均利用率。在端侧流式视频处理场景下，由于输入特征图尺寸大、卷积核相对适中、模型拓扑固定，通道广播、权重静止、激活值滑窗行复用、输出部分和累加四层组合是较为合适的复用策略，本论文在[3.6](#数据复用与多级存储层级)节展开分析。

### 2.4 硬件加速基础技术

###  流水线设计

流水线是数字硬件中提升吞吐率的基本手段，其核心思想是将一个长组合逻辑路径切分为多级时序子路径，相邻级之间用寄存器隔开，使得各级在每个时钟周期内可以并行处理不同的数据。设流水线划分为$N$级，理想情况下吞吐率可由原先的$1\text{/}\left( N \cdot t_{stage} \right)$提升至$1\text{/}t_{stage}$，其中$t_{stage}$是单级延迟。流水线带来的额外代价主要包括寄存器面积、流水线启动延迟与流水线冲刷损失。在卷积加速器中，乘法器与加法树往往位于时序最长路径上，将其切分为乘法级、加法树第一级、加法树第二级等多级流水线段，是提升时钟频率的有效手段。

###  行缓存与窗口生成

卷积运算需要在每一步访问输入特征图上一个$K \times K$的局部窗口，若每次都从片外存储读取整个窗口，将带来巨大的带宽压力。行缓存（line
buffer）通过在片上保存最近的$K$行输入像素，使得当卷积核滑动到下一像素位置时，可直接在片上读出对应的$K \times K$窗口而无需重复访问片外。行缓存通常采用环形缓冲（ring
buffer）的写入策略：当第$K + 1$行像素流入时，覆盖最早一行所占的存储位置，从而以固定的存储容量持续支持任意高度的输入特征图流式输入。在端侧流式应用中，行缓存承担着连接片外像素流与片上MAC阵列的缓冲职责。

###  握手协议

数字模块之间的数据传输需要明确的同步机制以应对生产者与消费者之间的速率失配。valid-ready握手协议是一种在异步速率耦合中广泛采用的双向握手机制：生产者在数据有效时拉高valid信号，消费者在可接收数据时拉高ready信号，仅当valid与ready在同一时钟沿同时为高时数据才被认为完成传输，如图2.3所示。

![[]{#_Ref229576151 .anchor}图2.3
流水线握手协议时序图](.docx-media/media/image5.png){alt="P403#yIS1"
width="3.25in" height="1.681097987751531in"}

该协议的优点在于：双方各自管理自身的状态，互不干涉；任意一方反压时另一方自动停顿，不需要中心仲裁；多个模块可级联组成无中心FSM的流水线。在CNN加速器内部，valid-ready握手是连接行缓存、乘加阵列、部分和累加器、输出缓冲等模块的标准接口形式。

###  总线协议AXI

AXI（Advanced eXtensible
Interface）总线是ARM公司提出的面向高性能片上系统的标准总线协议，分为两类：AXI4-Full面向高吞吐数据传输，支持突发读写、乱序事务与多ID并发，常用于加速器与外部DDR控制器之间的批量数据搬运；AXI4-Lite面向低吞吐配置寄存器访问，仅支持单拍读写，用于主机到加速器配置寄存器（Control
Status
Register，CSR）的写入与状态回读。AXI基于valid-ready握手构建，可与加速器内部握手接口自然衔接。加速器顶层通常由AXI4-Lite从接口接收主机配置和AXI4主接口发起DDR突发读写组成。

##  非一致性内存访问架构

非一致性内存访问（Non-Uniform Memory
Access，NUMA）是多核体系结构中描述内存访问延迟非对称性的基本概念：处理核访问邻近本地存储节点延迟较低，访问远端节点需穿越互连网络且延迟显著上升；多核争用同一远端节点时互连拥塞还会放大尾部延迟。Hennessy和Patterson^[42]^指出在核数超过8之后集中式共享存储的总线带宽与一致性开销成为瓶颈，因此现代片上系统普遍采用分布式本地存储加片上互连的NUMA结构。如图2.4所示为NUMA拓扑图。

NUMA特征同样体现在多核加速器中：Eyeriss
v2^[14]^为多PE簇配置独立私有SRAM并通过分层 mesh

### 2.7 模型量化基础

神经网络通常以FP32格式训练，但FP32模型直接部署到端侧设备在能耗、面积与延迟上难以满足约束。模型量化通过将权重与激活值用更低位宽的定点数表示，显著降低存储占用与乘加运算的硬件代价。量化白皮书^[43]^将主流量化算法归为训练后量化（PTQ）与量化感知训练（QAT）两类：PTQ在已训练的浮点模型上直接进行量化，用少量校准数据统计权重与激活值数值分布，按线性映射量化为定点张量；在多数视觉分类与检测任务上PTQ可将FP32量化至INT8并保持1%
以内精度下降^[43]^，广泛应用于工业界。QAT在训练阶段引入量化噪声模拟，通过反向传播让权重对量化误差自适应，实施成本更高但在4位等低比特场景下精度优于PTQ。

如图2.6所示，INT8量化推理中权重量化至8位、偏置量化至32位以避免大数累加溢出：卷积或全连接层执行8位定点乘法，结果累加进32位部分和，累加完成后与32位偏置相加，再经过激活函数与重量化逻辑得到8位输出。硬件实现中INT8乘法器面积约为FP32乘法器的1/10以下，是端侧CNN加速器最常见的精度选择。

### 2.8 本章小结

本章梳理了CNN加速器设计依赖的理论基础。卷积层在整网计算量中占主导地位，多通道展开决定了通道切片的硬件必要性；权重静止、输出静止、行静止三种典型数据流在复用对象与互连复杂度上的差异为数据通路设计提供了选型依据；流水线、行缓存与valid-ready握手是模块实现的基础，AXI协议规定了加速器对外接口形态；NUMA体系结构与四级存储层级的访存延迟与能耗梯度对应数据复用机制的设计；INT8量化为MAC阵列的位宽选型提供了理论支撑。

#  总体方案

##  引言

面向端侧流式计算场景的卷积加速器FLUX_CNN在算力、功耗、面积与调度灵活性之间存在多重权衡。以端侧推理在小面积、低功耗下保持稳定吞吐为目标，加速器采用控制核与加速核分工的双层结构：加速核内由5个流水模块加1个共享配置寄存器堆通过valid-ready握手互联，对外暴露AXI4主接口与AXI-Lite从接口；多核扩展层提供多核配置。调度方案采用核内寄存器配置与核外宏观指令流相结合的分层结构，并在$16 \times 16$MAC阵列上同时实施输入通道广播、权重静止、激活值滑窗行复用与输出部分和累加四层复用数据流。

##  设计目标与约束

端侧流式计算场景具有三个共性需求。一是输入数据持续到达，加速器需要支持任意$H \times W$尺寸的特征图，而不是只能处理一张图后停机；二是供电与散热受限，单帧推理的能耗预算往往在毫焦量级；三是部署形态多样，从智慧城市的视频监控盒到工业相机的缺陷检测板，再到消费电子的手势识别芯片，对面积与成本敏感。这些需求共同决定了端侧加速器与云端加速器在设计目标上的差异：端侧不追求峰值算力，而追求在小面积、低功耗下保持稳定的实测吞吐。

第一个目标是算力---功耗---面积（PPA）的均衡。本设计选用$16 \times 16$的INT8乘加阵列（$NUM\_ COL = NUM\_ PE = 16$，$DATA = 8 bi$t，$PSUM = 32 bit$），共256个MAC单元，单时钟周期理论峰值$256 OPS$。INT8量化后乘法器面积约为32位浮点的十分之一以下，单次乘加的能耗也大幅下降。乘加阵列规模选$16 \times 16$而非更大，是因为端侧典型卷积层的$C_{in}/C_{out}$经常出现16量级，如ResNet早期层$C_{in} = 3, 64$，MobileNet深度卷积$C_{in} = 1$，更大的阵列在这些层会出现严重的列空转，得不偿失。

第二个目标是支持任意输入尺寸而不让片上存储成为瓶颈。本设计将片上输入特征图缓存（Input
Feature Buffer, IFB）固定为2048 word、输出特征图缓存（Output Feature
Buffer, OFB）固定为2048
word，在编译期按行粒度切分，使IFB与OFB形成环形缓冲。一张$480 \times 640$的VGA图像（约4.9
MB）只占用IFB中10
KB量级的滚动窗口，仍能在一次启动内单遍跑完，不需要把整图全部装入片上。

第三个目标是片上控制电路的简单性。中心FSM在层数变化、切片维度变化、输入尺寸变化时都需要重新设计状态机迁移图，工程代价高、复用性差。本设计令加速核内的5个流水模块各自维护本地计数器，模块之间用valid-ready握手串联，没有中心FSM；任何一段反压时，上游自动停顿、下游自动等待，整条流水以弹性方式松耦合协作。这一选择把"哪一层在哪一周期做什么"的复杂度从硬件状态机转移到编译器派生的配置寄存器与宏观指令流。

第四个目标是调度的层次化与可扩展。单层卷积的循环结构包含$C_{out,slice}/C_{in,slice}/y_{out}/x_{out}/k_{x}/k_{y}/p_{e}$七层嵌套，本设计将这七层循环静态映射到固定硬件，由编译器在配置寄存器中写入各层循环边界；多层之间的串接、多核之间的协同则通过Task
Descriptor描述，不依赖主机逐层介入。

##  总体架构

针对上述设计目标，FLUX_CNN加速器的总体结构如图3.2所示。系统整体采用控制核与加速核分工的层次化结构：控制核负责系统级管理、外部数据接口与宏观调度，加速核（以下简称核）专注卷积层的高效计算。控制核与核之间通过AXI4总线连接，AXI-Lite通道用于配置寄存器读写，AXI4完整通道用于权重、特征图与描述符的批量搬运。

FLUX_CNN对外仅暴露两个接口：一个AXI4主接口与一个AXI-Lite从接口。AXI4主接口连接外部DDR控制器，承担IFM、OFM、权重、偏置与残差数据的批量搬运；AXI-Lite从接口连接控制核，用于核启动信号、状态寄存器与少量启动期参数的读写。这一接口形态使加速器易于挂接到Zynq、定制SoC或其他ARM/RISC-V控制核为主的端侧平台，集成边界清晰。

加速核内部由5个数据通路模块加1个共享配置寄存器堆（cfg_regs）组成。如图3.3所示核内数据通路结构。第一个模块是行缓存模块（line_buffer），承担将片外像素流转为片上$K \times K$卷积窗口的职能，输出激活值向量给MAC阵列；同时维护行级环形缓冲并通过行信用机制向IDMA反压。第二个模块是MAC阵列模块（mac_array），由$16 \times 16$PE共256个INT8乘加单元组成，列间广播激活值，每列对应一个输出通道，列内16
PE沿$C_{in}$方向并行累加，单周期消耗1拍激活值向量与16列权重，输出16路部分和。第三个模块是部分和累加模块（parf_accum），对来自MAC阵列的部分和按$C_{in}$切片维度累加；累加器拆分为16个独立SRAM实例（每列一个，外壳共享写地址与写使能），每列容量$PARF = 32$，匹配输入通道广播下16路$C_{out}$并行与激活值滑窗行复用下32个相邻滑窗并发的数据流形态。第四个模块是输出特征图写出模块（ofb_writer），负责接收累加完成的部分和，依次完成偏置加、量化移位、饱和截断到INT8、可选的残差融合，再写入OFB。第五个模块是权重缓存模块（wgt_buffer），从权重缓冲（WB，1024
word）侧路向MAC阵列各列分发权重，配合权重静止数据流让权重在一段时间内保持稳定。

5个模块之间用valid-ready握手互联，任意一方反压时另一方自动停顿。模块各自维护本地计数器，依次走完$C_{out,slice}/C_{in,slice}/y_{out}/x_{out}/k_{x}/k_{y}/p_{e}$循环；不同模块的计数器自然形成流水关系，没有中心仲裁。模块边界处的弹性拼接使得反压期间在途数据不丢失，相邻tile之间也允许填充与排空重叠，相邻轮次之间允许指针跨界连续推进，提升了整条流水线的稳态利用率。

![[]{#_Ref229581634 .anchor}图3.3
核内数据通路结构图](.docx-media/media/image11.png){width="4.862576552930884in"

DMA子系统位于加速核外、对接AXI4主接口。如图3.3所示DMA子系统结构。DMA子系统由1个Xilinx
AXI DataMover
IP加多个自研控制器组成。axi_dm提供MM2S与S2MM两条搬运通道：MM2S通道由用于拉取输入特征图的idma_ctrl与用于拉取权重的wdma_ctrl通过mm2s_arb串行仲裁共享，S2MM通道由用于写出输出特征图的odma_ctrl独占。另有rdma_ctrl负责拉取偏置与残差数据，描述符获取引擎DFE负责按宏观指令流拉取描述符链表。多个控制器的请求经axi_m_mux聚合后挂到唯一的AXI4主接口。这一组织方式让加速器对外只表现为一对AXI接口，简化SoC集成的同时保留了内部多通道并行的能力。

cfg_regs是加速核与外部交互的配置寄存器堆，采用双写口设计：一个写口接AXI-Lite
CSR，由控制核写入启动期4个寄存器；另一个接sequencer，由sequencer消费DFE拉取的CFG_WRITE描述符流写入逐层配置，DFE仅负责把描述符链表从DDR拉进描述符FIFO，CFG_WRITE类型的描述符再由sequencer从FIFO中取出并写入cfg_regs的描述符写口。这样控制核与描述符通路互不干扰，描述符流可以批量搬运一层卷积所需的50余个配置寄存器值，控制核只需在启动时写4个寄存器并触发一次启动。

为支持更高吞吐，加速器在加速核之上提供多核扩展层multicore。多核扩展层包含$N$个加速核、基于Xilinx
SmartConnect
IP的AXI互连交换、AXI-Lite一对多分发。多核之间采用W维切片调度：每核处理一段sub_W子图加上必要的边界冗余列；相邻核之间通过跨核SRAM直送把上一层OFM直接写入下一核的IFB区域，无需经过外部DDR中转。多核扩展层不改变单核数据通路，只在最外层包络上接入$N$份加速核与互连，单核与多核共享同一套cfg_regs与编译流程。

##  调度方案

加速器的核心命题是软硬协同的分层调度：把卷积循环嵌套这一具有静态结构的部分留给硬件直接展开，把任务级的灵活性留给编译器与宏观指令流。这样硬件不必在每层卷积参数变化时重新设计状态机，编译器也不必关心每周期PE该做什么。

第一层调度位于核内，基于配置寄存器与6层FSM。一层卷积的硬件状态由cfg_regs内50余个配置寄存器完整描述，包括：

（1）
循环边界：$H_{in}$、$W_{in}$、$C_{in}$、$C_{out}$、$K$、$stride$、$pad$;

（2） 片上缓冲基址：IFB、WB、OFB、bias、shortcut;

（3） 量化参数：移位量、零点、饱和上下限;

（4） 调度参数：$C_{in,slice}$、$C_{out,slice}$、$tile_{w}$。

一旦配置寄存器写入完成并触发start_layer，核内6层嵌套循环依次推进：

（1） cs: $C_{out,slice}$，遍历输出通道切片；

（2） yout: 输出行；

（3） tile: W维tile；

（4） cins: $C_{in,slice}$累加

（5） round: 同一tile内的累加轮次；

（6） pos: MAC阵列位置。

每一层循环由对应模块的本地计数器自维护，循环边界来自cfg_regs，循环嵌套关系隐含在模块互连中。一层卷积处理完成后，核拉起done_sticky，等待下一次启动。

height="3.7550404636920387in"}

第二层调度位于核外，基于宏观指令流与Task
Descriptor。多层卷积的串接通过描述符链表组织：每层对应若干描述符，分为：

（1） 输入特征图拉取IDMA_DESC；

（2） 权重拉取WDMA_DESC；

（3） 配置寄存器写入CFG_WRITE；

（4） 输出写出ODMA_DESC。

描述符链表预先由编译器生成、放置在DDR中，描述符获取引擎DFE在启动后自动按链表顺序拉取并分发到对应控制器。控制核在启动时只需写入4个启动寄存器，然后触发start_dfe，整条多层链路可在不需要逐层介入的情况下跑完。这一设计将控制核的AXI-Lite写次数从原本的50余次/层降到4次/层，显著降低主机侧调度负担。

第三层调度跨多核展开，仍然走宏观指令流。多核场景下，编译器在调度阶段为每一核独立生成一份描述符链表，链表中包含本核处理的W切片范围、所需的边界冗余列、跨核SRAM直送的目标地址等。核间的同步通过cfg_regs中的握手寄存器与跨核SRAM直送的写完成信号完成，不需要中央调度器。各核启动后并行运行，在层边界处通过一次跨核握手交换准备状态，进入下一层。

层次化调度的设计选择让加速器具备较强的可扩展性。增加新的卷积变只需扩展编译器；增加新核数也不需要改单核RTL，只需扩展多核扩展层与编译器侧的切片逻辑。硬件的复杂度集中在循环嵌套的静态映射上，可在综合后稳定下来。

##  数据流选择

加速核的数据流选择需要在权重复用、激活值复用、部分和复用三者之间作出取舍。本设计在$16 \times 16$MAC阵列上同时实施四层数据流复用：输入通道广播、权重静止、激活值滑窗行复用与输出部分和累加。四者分别从输出通道维、时间维、空间W维与累加维降低片上访存频度，与卷积循环嵌套的不同维度一一对应。

输入通道广播让16个输入通道的激活值向量在同一拍内被16列PE共享消费。每周期，行缓存模块对外输出1拍激活值向量，包含当前空间位置上16个$C_{in}$通道的像素值；这1拍向量同时广播到16列PE，列c的16个PE各自以16个$C_{in}$的激活值乘以对应权重并沿$C_{in}$维累加，产出输出通道的1路部分和。同一拍激活值跨16列共享、各列权重独立，使激活值的片上分发开销与输出通道数解耦------扩展输出通道并行度只需增加列数，无需复制激活值通路。图3.5（a）为输入通道广播的数据复用示意图。

（b）权重静止示意图

权重静止让WRF内的权重在连续32个周期内保持不变。本设计的权重静止不仅体现为"一层内权重不出WB"，更体现为更细粒度的"32周期内权重不出WRF"。这一性质来自于激活值滑窗行复用所确立的"32周期处理32个相邻空间位置"的执行顺序：32个滑窗位置共用同一组（$C_{in}, C_{out}$）权重，因此每32拍才需要从WB向WRF重载一次，权重更新频率降至原来的$1/32$，权重侧的片上带宽与功耗随之同步下降。图3.5（b）为权重静止的数据复用示意图。

激活值滑窗行复用是本设计的关键机制：激活值寄存器堆ARF并不缓存单个$K \times K$卷积滑窗的元素，而是缓存当前行内32个连续W维像素。MAC阵列在32个周期内对这32个相邻空间位置的滑窗依次发起卷积，共用同一组权重并各自累加自身的部分和------视上层时序为\"同时进行32个滑窗的计算\"。当32周期完成、滑窗向W维右移一段时，下一组滑窗需要的像素是2\~33号，其中2\~32号已经存在于ARF内，行缓存模块只需向ARF补入1个新像素即可；这种逐拍滑动的复用使行缓存到ARF的写入频度降至$1/32$，ARF成为PE端激活值访问的主入口。图3.6为激活值滑窗行复用的示意图。

![[]{#_Ref229590765 .anchor}图3.6
数据复用-激活值滑窗行复用示意图](.docx-media/media/image15.png){width="5.3337521872265965in"
height="2.5565507436570427in"}

部分和寄存器堆PARF对应32个并行滑窗的部分和聚合：每列配备32个累加单元，第$i$个PARF单元持续累加第$i$个滑窗位置在$C_{in}$维与$K^{2}$维上的所有乘加结果。$K \times K$内偏移与$C_{in}$切片由FSM按节拍推进，PARF在一个完整卷积循环结束时直接给出32个相邻空间位置的最终部分和向量。16列PARF使用各自独立的SRAM端口，列间不发生端口冲突，结构上完全并行。图3.7为输出部分和累加的示意图。

![[]{#_Ref229590766 .anchor}图3.7
数据复用-输出部分和累加示意图](.docx-media/media/image16.png){width="2.823549868766404in"
height="2.0833333333333335in"}

四层数据流复用的组合让$16 \times 16$MAC阵列在物理实现层面呈现三维对称结构：

W维并行32路：时分复用、单PE列内推进；

$C_{in}$维并行16路：列PE同时累加；

$C_{out}$维并行16路：列PE同时输出。

权重静止把权重带宽折减至$1/32$；激活值滑窗行复用把行缓存的带宽折减为$1/32$；输入通道广播把激活值的列间分发开销折减为$1/16$；输出部分和累加让部分和始终留在阵列内的PARF中，完全不出阵列。四者叠加使16×16
MAC阵列在端侧严格的功耗限制下保持稳定的高利用率。

## 数据复用与多级存储层级

FLUX_CNN加速核的数据通路按访问能耗梯度自上而下划分为五级存储层级：计算单元、寄存器堆、核内SRAM、跨核SRAM、片外DRAM。各级单次访问能耗[]{.mark}图3.8所示。从计算单元到DRAM五级之间，单次访问能耗跨度达约640倍：DRAM单次访问的能耗约等于640次MAC运算或80次核内SRAM访问的能耗之和。因此片上数据通路的设计目标是把绝大多数访问停留在compute与register两级，仅在数据进入和退出阵列时穿越SRAM与DRAM。

FLUX_CNN的四层数据流复用机制------输入通道广播、权重静止、激活值滑窗行复用、输出部分和累加------分别对应卷积循环嵌套的四个维度，每一层复用机制把对应维度的访问压低一个存储层级，最终使绝大部分数据访问停留在寄存器堆与核内SRAM两级，将DRAM访问压低到层边界仅触发一次的程度。

输入通道广播对应$C_{in}$维度。16列PE在同一拍共享同一组16-$C_{in}$激活向量，激活总线翻转规模由每列独立降为列间共享，激活值的列间分发功耗降至1/16。该机制把列方向上的功耗开销从SRAM层级压低到Register层级。

![[]{#_Ref230002080 .anchor}图3.8
FLUX_CNN各级单次访问能耗阶梯](.docx-media/media/image17.png){width="4.600009842519685in"
height="2.2556649168853893in"}

权重静止对应$K^{2}$卷积核维度与$W_{out}$输出宽度维度。WRF内权重在32个连续输出像素的计算周期内保持不变，WB至WRF的读取频率仅为$1/\left( K^{2} \cdot W_{tile} \right)$。每条权重从WB加载到WRF一次后，被32个W维输出像素重复使用32次。该机制把权重的供给开销从SRAM层级压低到register层级。

激活值滑窗行复用对应$K \times K$卷积窗口的空间维度。ARF缓32
个连续W维像素，6层FSM按$k_{x}/k_{y}$偏移直接取值，相邻输出位置之间的输入激活复用率达$K \cdot K - K$。该机制把激活值的空间复用从SRAM层级压到register层级。

输出部分和累加对应$C_{in}$通道累加维度。32路部分和在PARF内连续累加$\left\lceil C_{in}/16 \right\rceil$轮直至该输出位置全部$C_{in}$累加完成，期间部分和始终不出阵列。该机制把部分和的累加开销限制在register层级，写回OFB仅在每个输出位置触发一次。

四层复用叠加后，理想情况下每次MAC运算对应的存储访问占比近似为：

$$\begin{array}{r}
\left\{ \begin{array}{r}
\# MAC触发1次计算\ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ 1pJ \\
\# 1/16次register层级读写\ \ \ \ \ \ 0.25pJ \\
\# 远小于1次的SRAM读写\ \ \ \ \ \ \ 1pj \\
\# 0次DRAM读写\#\#\ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ 0pJ
\end{array} \right.\ 
\end{array}$$

第[5.7.6](#数据复用效果分析)节将通过实验量化各层复用机制对端到端能耗的实际贡献。

### 3.6 本章小结

本章给出了FLUX_CNN加速器的总体方案。面向端侧流式计算场景下算力---功耗---面积均衡、任意输入尺寸支持、片上控制简单性与调度层次化四项约束，加速器在整体上采用控制核与加速核组成的双层结构：加速核内部由5个数据通路模块加1个共享配置寄存器堆通过valid-ready握手互联，外部1个AXI4主接口与1个AXI-Lite从接口；多核扩展层在不改动单核RTL的前提下提供多核配置。调度方案在核内采用配置寄存器与6层FSM完成单层全部循环嵌套展开，在核外采用宏观指令流与任务描述符链表完成跨层与跨核任务编排，使硬件保持最简静态结构而灵活性集中在编译器侧。

数据流层面，加速核同时实施输入通道广播、权重静止、激活值滑窗行复用与输出部分和累加四层复用。四层复用与卷积循环嵌套分别对应，把片外带宽、片上分发与累加功耗按维度分层折减。这些方案共同构成FLUX_CNN加速器具体实现的整体框架。

#  加速器具体实现

##  引言

FLUX_CNN加速器的具体实现按模块顺序展开。加速核内5个数据通路模块：行缓存模块、MAC阵列模块、部分和累加模块、SDP后处理模块、权重缓存模块承担激活值像素供给、乘加计算、部分和累加、量化后处理与权重供给五项职责；配置寄存器与6层FSM协同完成单层全部调度；编译器侧的Y维折叠与空间到深度两项变换覆盖小$C_{in}$与大步长两类低利用率场景；DMA子系统、AXI接口集成与多核W切片扩展层承接片外数据搬运与多核扩展；最后给出$16 \times 16$INT8
MAC阵列在DSP48E1块上的跨列复用映射方案。

##  行缓存模块

行缓存模块（line_buffer）承担把片外IFM行流组织为片上行级环形缓冲，并按FSM节拍向MAC阵列发射16-$C_{in}$激活值像素的职能，是片外IFM与MAC阵列之间的桥梁。它本身并不输出$K \times K$窗口------$K \times K$窗口的组装由MAC阵列模块在（$k_{x}, iss_{pos}$）内循环ARF按地址偏移取值完成，使该模块的对外表现为"每周期一拍16-$C_{in}$像素向量"。如图4.1所示为$K = 3$时，行缓存模块的数据排列格式时序图。

![[]{#_Ref229648932 .anchor}图4.1
行缓存数据排列格式时序图（K=3）](.docx-media/media/image18.png){width="6.25984251968504in"
height="2.9316502624671914in"}

行缓存模块的存储核心是一块容量2048
word的IFB，按行粒度组织为环形缓冲。每行宽度为$W_{in}$，所需行数为$strip_{rows}$，由编译器在cfg派生阶段算出，${strip}_{rows} \times W_{in}$个word不超过IFB容量。环形缓冲在物理层面是一段连续SRAM，逻辑层面通过$mod strip_{rows}$取地址实现。一张$480 \times 640$的VGA图像约4.9
MB，IFB仅占用10 KB量级即可流式跑完。

紧邻IFB与MAC阵列之间是激活值寄存器堆ARF。ARF并不缓存单个$K \times K$卷积窗口的全部元素，而是按当前$k_{y}$偏移行缓存最多32个沿W维连续的16-$C_{in}$像素向量。在$stride = 1$与$K > 1$的常规情形下，行缓存模块切换至滑窗复用模式，让ARF在一个$k_{y}$行内承担MAC阵列内循环全部的激活值读出，使IFB读出频度降至每个$k_{y}$行一次；在$stride > 1$或$K = 1$的情形下，ARF等价于ring-FIFO，每拍读IFB一次发射给MAC阵列。

行缓存模块的两种模式由cfg_arf_reuse_en字段选择，覆盖完整的形状空间。

模式A：$reuse_{en} = 0$，$stride > 1$
或$K = 1$。ARF用作ring-FIFO：每拍当issue_ok_std成立时，根据当前6层FSM内层计数器（$k_{x}, iss_{pos}$）算出虚拟坐标（$src_{y}, src_{x}$）与IFB物理地址$ptr_{kx,base} + iss_{offset}$发起1拍IFB读，1拍SRAM延迟后将读出的16-$C_{in}$像素写入；下游MAC阵列以$act_{valid} = \left( fifo_{count} > 0 \right)$握手。该模式下ARF的写入与读出频度均等于MAC阵列的发射频度，不构成滑窗复用，主要服务于点卷积与降采样卷积两类。

模式B：${reuse}_{en} = 1$*，*$stride = 1$且$K > 1$。ARF用作线性FILL/CONSUME区，把单一$k_{y}$行内的滑窗激活值复用集中到ARF内部。具体而言，编译器在cfg派生阶段算出$cur_{fill,len} = tile_{w} + K - 1$并保证其不超过${ARF}_{DEPTH} = 32$；行缓存模块进入新（$cins, tile, k_{y}$）时先进入FILL阶段，按$fill_{pos}$从0线性推进到$cur_{fill,len}$，每拍读一次IFB。FILL与CONSUME并行：MAC阵列同时启动（$k_{x}, iss_{pos}$）内循环，按组合索引$rd_{idx} = k_{x} + iss_{pos}$直接读出$ARF\lbrack rd_{idx}\rbrack$，仅当该位置已被填满时$act_{valid}$才拉起。

模式B体现了激活值滑窗行复用的物理实现：MAC阵列在一个$k_{y}$行内沿（$k_{x}, iss_{pos}$）推进，$iss_{pos}$遍历$tile_{w}$个相邻输出空间位置，$k_{x}$遍历$K$个核内偏移，因此每个$iss_{pos}$滑窗位置共需$tile_{w} \times K$次ARF读出，而ARF总写入只有$cur_{fill,len} = tile_{w} + K - 1$次------相邻空间位置的滑窗共享了$K - 1$个像素。

Padding处理采用虚拟坐标越界判定：计数器选择性写入零向量而非SRAM读出值。该方案使行缓存模块在统一的发射节奏内吸收任意pad配置，无需为pad区单独发IFB读。

对外接口为四路：上游IFB
SRAM读端口、下游MAC阵列激活值接、与IDMA控制器的握手、以及cfg只读端口。模块内部不维护FSM，仅以（$y_{out}, cs, tile, cins, k_{y}, k_{x}, iss_{pos}$）
7级本地计数器自循环，并按外层进位级联推进物理地址累加器，循环边界与地址步进全部由cfg_regs在层启动时一次性写入。

##  乘加阵列模块MAC

乘加阵列模块MAC（mac_array）是加速核的算力核心，承担卷积层的乘加运算。如图4.2所示MAC阵列模块结构图。

![[]{#_Ref229596560 .anchor}图4.2
MAC阵列模块结构图](.docx-media/media/image19.png){width="3.8224879702537184in"
height="3.5652176290463693in"}

注1）图里仅画出了$8 \times 8$阵列，实际MAC设计阵列为$16 \times 16$

MAC阵列模块由$16 \times 16$
PE共256个INT8乘加单元组成。16列在结构上彼此独立，每列对应一个输出通道；列内16个PE沿$C_{in}$方向并行排布，承担单输出通道在16个输入通道方向上的并行乘加。二维结构与卷积循环嵌套中的$C_{out}$维与$C_{in}$维自然对齐：列方向广播激活值、列内方向沿$C_{in}$累加。

MAC阵列模块采用输入通道广播+权重静止+激活值滑窗行复用+输出部分和累加的复合数据流。

第1步，权重加载：权重缓存模块（wgt_buffer）将当前$C_{out,slice}$所需的全部权重从权重缓冲（Weight
Buffer，WB）一次性读入权重寄存器堆（Weight Register
File，WRF=32），WRF内的权重在连续$32 \times C_{in,slice}$个周期内保持不变。

第2步，激活值缓存：行缓存模块输出的当前窗口激活值向量进入激活值寄存器堆（Activation
Register
File，ARF=32），32拍内由FSM按${ k}_{x}, k_{y}$偏移在ARF内取值；当32个滑窗完成后，下一组所需像素中2\~32号仍在ARF内，行缓存只需补入1个新像素即可推进。

第3步，广播与乘加：每周期由ARF广播1拍激活值向量到16列，每列消费各自的WRF项产生1路输出通道的16路PE并行乘积，列内16路乘积经一棵加法树规约为1路$PSUM = 32 bit$部分和。

第4步，部分和发射：每周期16列同时向部分和累加模块发射16路PSUM。

MAC阵列模块的并行度可分解为三个维度。$C_{out}$维并行度16（列数）、$C_{in}$维并行度16（每列内PE数）、$K_{x}/K_{y}$维顺序展开（同一窗口在$K^{2}$个子周期内顺次计算）。理论峰值算力为：

$$\begin{array}{r}
\frac{256}{c_{y}} \times F_{\max}\ ops
\end{array}$$

当$C_{in} < 16$时，$C_{in}$维存在列空转，需配合编译器侧Y维折叠优化；当$C_{out} < 16$时，硬件不复用，对应PE列空转，不在此层做硬件级优化。

MAC阵列模块对外提供三路接口。上游接行缓存模块的窗口口；侧路接权重缓存模块的权重口；下游接部分和累加模块的部分和。模块内部由（$k_{x}, k_{y}, cin_{pe}$）三级本地计数器自维护，循环边界由cfg_regs提供。每个PE由1个INT8乘加器构成，256个PE构成本章MAC阵列的核心计算资源。

##  部分和累加模块

部分和累加模块位于MAC阵列模块下游，对16列发射的部分和按$C_{in,slice}$维度累加，等当前（$y_{out}, x_{out}$）输出位置在所有$C_{in,slice}$上累加完毕后向SDP后处理模块发射。如图4.3所示部分和累加模块结构图。

部分和累加模块的存储核心是部分和寄存器堆（Partial-Sum Register
File，PARF=32），逻辑容量为16列×32项。在物理实现上，本设计将PARF拆分为16个独立SRAM实例：

> $$\begin{array}{r}
> parf_{col} \times NUM_{COL} = 16
> \end{array}$$

每列一个SRAM，避免16列共用一个大SRAM时的端口冲突。16列共享同一组写地址与写使能，由外壳模块统一驱动；每列的写数据来自本列的MAC阵列输出PSUM，每列的读数据独立返回，各列的累加在结构上完全隔离。

![[]{#_Ref229597255 .anchor}图4.3
部分和累加模块结构图](.docx-media/media/image20.png){width="4.671102362204724in"
height="3.4070811461067367in"}

部分和累加模块的实现流程分为三步。

第1步，读出：当$C_{in,slice}$索引大于0时，从PARF当前（$tile_{w}, C_{out,col}$）槽位读出已累加的部分和。

第2步，累加：将本周期MAC阵列发射的16路PSUM与读出的累加值相加，结果回写PARF同一槽位；当$C_{in,slice} = 0$时跳过读出，直接写入新值。

第3步，发射：当一个（$tile_{w}, C_{out,col}$）槽位的所有
$C_{in,slice}$累加完，将累加结果通过valid-ready握手发射到SDP后处理模块。

PARF=32容量对应一个$C_{out,slice}$内32个$tile_{w}$输出位置的部分和缓存------这32个位置正是激活值滑窗行复用中并发处理的32个相邻W维滑窗。当$tile_{w}$输出数大于32时，编译器会进一步切分tile，由6层FSM中的tile维循环承担。每列独立SRAM让16列累加在物理端口上完全隔离，匹配MAC阵列模块"输入通道广播$\times$输出部分和累加"双维度并行的数据流形态。

部分和累加模块对外提供两路接口。上游接MAC阵列模块的部分和口；下游接SDP后处理模块的累加完成口。模块内部由（$tile_{w}, C_{in,slice}$）二级本地计数器自维护，循环边界由cfg_regs提供，$C_{in,slice} = 0$与$C_{in,slice,total} - 1$两个边界条件分别控制累加器初值与发射时机。

##  后处理模块SDP

SDP后处理模块（ofb_writer）位于部分和累加模块下游，对累加完成的32位部分和依次完成偏置加、量化移位、饱和截断到INT8、可选的残差融合，再写入OFB，承担INT8量化推理通路上从PSUM到OFM的后处理链。如图4.4所示SDP后处理模块结构图。

![[]{#_Ref229597602 .anchor}图4.4
SDP后处理模块结构图](.docx-media/media/image21.emf){width="5.590551181102362in"
height="1.5354330708661417in"}

SDP后处理模块的实现流程分为五步。

第1步，偏置加：从偏置寄存器堆读出当前输出通道的32位偏置，与累加完成的32位部分和相加。偏置由RDMA控制器从DDR中预先拉入寄存器堆。

第2步，量化移位：对偏置加结果按配置的右移量进行算术右移，将32位部分和按层量化尺度缩放到目标位宽。

第3步，饱和截断：对移位结果按上下限做饱和裁剪，超出范围的值钳位到边界。

第4步，残差融合：当当前层启用残差时，从残差缓冲读出对应空间位置的残差值，进行通道级缩放后与饱和结果相加，结果再次饱和到INT8。残差缓冲由上一层的OFM直接写入，无需经主机介入。

第5步，OFB写入：将最终INT8结果按（$y_{out}, x_{out}, c_{out}$）地址写入OFB
ring。

SDP量化与残差融合的全部配置寄存器详见附录

[表A.6](#_Ref229686989)。

SDP后处理模块在ofb_writer内集成偏置加、量化移位、饱和、残差融合，使ResNet残差通路在加速器内部一站式完成。Shortcut
Bank与bias_rf让残差加与偏置加都在片上完成，主机不需要为每层介入；ofb_writer内部的SDP链以INT8后处理形式落地，单层cfg_regs配置完成后整段后处理无需进一步指令。

SDP后处理模块的OFB写入端同样按行粒度组织为环形缓冲。每写完一行向ODMA控制器汇报"写指针+1"，ODMA控制器据此发起S2MM突发写入DDR。当ODMA排空一行后向ofb_writer拉起row_credit，让ofb_writer继续写入下一段。OFB
ring的$strip_{rows}$由编译器派生，与IFB ring相互独立。

SDP后处理模块对外提供三路接口。上游接部分和累加模块的累加完成口；侧路接bias_rf与Shortcut
Bank两个寄存器堆；下游接OFB写口与ODMA行信用口。模块内部由（$y_{out}, x_{out}, c_{out,col}, c_{out,slice}$）四级本地计数器自维护。

### 残差通路

ResNet系列网络的残差连接要求当前层的卷积输出与若干层之前的特征图按位融合。若每次残差融合都从片外DDR重拉残差像素，将引入与卷积主通路同量级的输入带宽开销，残差路径的访存延迟亦会与主路径串行叠加。SDP后处理模块在ofb_writer内集成残差缓冲（Shortcut
Bank）作为残差通路的片上输入端，使残差融合在加速器内部一站式完成，无需主机或主路径以外的访存介入。

Shortcut Bank的存储核心是一块容量为2048
word的SRAM，与IFB容量同量级，按行粒度组织为环形缓冲，按（$y_{out}, x_{out}, c_{out}$）地址按位读取INT8残差像素。在多核扩展层$N = 4$配置下，按多核W切片的容量划分，每核Shortcut
Bank的有效容量缩至2048 word。

Shortcut
Bank的填充由前序层的输出搬运直接完成。编译器在描述符链生成阶段决定哪一层的OFM作为残差源，将该层odma_ctrl的目标地址改为后续残差融合层的Shortcut
Bank物理地址；ODMA控制器据此发起S2MM突发写入Shortcut
Bank。残差缓冲填充复用OFM的写带宽，不经主机介入，不引入额外片外读带宽。

Shortcut
Bank的消费由SDP后处理链的残差融合触发。当cfg_regs中残差启用位拉起时，ofb_writer在完成"偏置加→量化移位→饱和截断"三步后，按当前（$y_{out}, x_{out}, c_{out}$）地址从Shortcut
Bank读出对应位置的INT8残差像素，按cfg_regs中shortcut_mult与shortcut_shift两参数完成通道级缩放，与本层量化结果按位相加，结果再次饱和到INT8后送入OFB写入步骤。整段残差融合在ofb_writer内组合实现，残差通路与主累加通路在SDP链内汇合，不引入额外的握手层级。

##  权重缓存模块

权重缓存模块（wgt_buffer）侧路供给MAC阵列模块的权重，配合权重静止数据流让权重在一段时间内保持稳定。

权重缓存模块的存储核心是权重缓冲（Weight Buffer，WB=1024
word）与权重寄存器堆（Weight Register
File，WRF=32）双层结构。WB是较大容量的SRAM，存放一层卷积所需的全部权重；WRF是更小、更靠近PE的寄存器堆，缓存当前$C_{out,slice}$所需的权重。

权重缓存模块的实现流程分为两步。

第1步，WB加载：在一层卷积启动时，WDMA控制器按（$C_{out}, C_{in}, k_{x}, k_{y}$）顺序将该层全部权重从DDR经MM2S通道写入WB。

第2步，WRF加载：在每个$C_{out,slice}$启动时，权重缓存模块将本$C_{out,slice}$所需的16列×32项权重从WB一次性读入WRF；之后整段$C_{out,slice}$内所有空间位置的乘加都直接消费WRF内的权重，不再访问WB。

WB容量按一层最大权重需求设计，每层加载一次；WRF容量按一个$C_{out,slice}$设计，$C_{out,slice}$内反复使用，稳态下不再访问DDR。

权重缓存模块对外提供两路接口。上游接WDMA控制器的写口；侧路接MAC阵列模块的权重广播口。模块内部由
（$C_{out}, C_{in}, k_{x}, k_{y}$）
四级本地计数器自维护，循环边界由cfg_regs提供。

##  编译器优化：Y维折叠 Ky-fold

针对$C_{\text{in}} < \text{NUM\_PE} = 16$的卷积层（如ResNet早期层$C_{\text{in}} = 3$、MobileNet深度卷积$C_{\text{in}} = 1$），MAC阵列模块在$C_{in}$维存在严重列空转，理论PE利用率仅$C_{\text{in}}\text{/}16$。在编译器侧提出Y维折叠（Ky-fold）优化，将$K_{y}$（卷积$Y$方向）维度折叠到$C_{in}$方向，在不改动RTL的前提下提升$C_{in}$维利用率。

Y维折叠的数学等价关系如公式$(4.3)$：

$$\begin{array}{r}
Y\left( y,x,c_{o} \right) = \sum_{k_{y} = 0}^{K - 1}{\sum_{k_{x} = 0}^{K - 1}{\sum_{c_{i} = 0}^{C_{\text{in}} - 1}{X\left( y + k_{y},\, x + k_{x},\, c_{i} \right)}}} \cdot W\left( k_{y},\, k_{x},\, c_{i},\, c_{o} \right)
\end{array}$$

为按${NUM}_{PE} = 16$的硬件$C_{in}$维容量分组折叠，定义每组容纳$g_{y} = \left\lfloor \text{NUM}\text{\_}\text{PE}\text{/}C_{\text{in}} \right\rfloor$个$k_{y}$行，以$C_{\text{in}} = 3$为例，$g_{y} = \left\lfloor 16\text{/}3 \right\rfloor = 5$，剩余$k_{y}$维分到$k_{y,\text{per}} = \left\lceil K\text{/}g_{y} \right\rfloor$组顺次执行。将组内$k_{y}$维与$C_{in}$维合并为$C_{in,fake}$维，得到公式$(4.4)$：

$$\begin{array}{r}
\left\{ \begin{aligned}
Y\left( y,x,c_{o} \right) & = \sum_{g = 0}^{k_{y,\text{per}} - 1}{\sum_{k_{x} = 0}^{K - 1}{\sum_{c_{f} = 0}^{g_{y} \cdot C_{\text{in}} - 1}{X'\left( y,\, x + k_{x},\, g,\, c_{f} \right)}}} \cdot W'\left( k_{x},\, g,\, c_{f},\, c_{o} \right) \\
c_{f} & = \left( k_{y\ }\text{mod}\text{ }g_{y} \right) \times C_{\text{in}} + c_{i} \\
g & = \left\lfloor k_{y}\text{/}g_{y} \right\rfloor \\
X'\left( y,x,g,c_{f} \right) & = X\left( y + g \cdot g_{y} + \left( k_{y}\text{ }\text{mod}\text{ }g_{y} \right),\, x,\, c_{i} \right) \\
W'\left( k_{x},g,c_{f},c_{o} \right) & = W\left( k_{y},k_{x},c_{i},c_{o} \right)
\end{aligned} \right.\ 
\end{array}$$

等效卷积的硬件视角变为$K_{y,\text{eff}} = k_{y,\text{per}}$、$C_{\text{in,eff}} = g_{y} \cdot C_{\text{in}}$的卷积。当$K \cdot C_{\text{in}} \leq \text{NUM\_PE}$，如ResNet首层$K = 3$、$C_{\text{in}} = 3$时，$k_{y,\text{per}} = 1$，整个$K_{y}$维一次折入，$C_{in}$维上PE利用率提升至$K \cdot C_{\text{in}}\text{/}16$；当
$K \cdot C_{\text{in}} > \text{NUM\_PE}$，如$K = 7$、$C_{\text{in}} = 4$时，$k_{y,\text{per}} > 1$，剩余$k_{y}$维仍走硬件$k_{y}$顺序展开。

Y维折叠的实现完全在编译器侧。

第1步，条件判定：scheduler在编译期判断$C_{\text{in}} < 16 \land K > 1$时启用Y维折叠。

第2步，权重重排：编译器把权重张量按$C_{in,fake}$索引重排，在DDR中按硬件视角的等效卷积布局摆放。

第3步，特征图复制：在Y维折叠路径下，输入特征图按$k_{y}$偏移在$C_{in}$维上复制，由IDMA控制器按重排后的布局拉取。

第4步，生成配置：scheduler用$C_{in,fake}$维度算$C_{in,slice}$数与循环边界，写入cfg_regs。整个过程无需RTL改动，硬件继续按普通卷积方式运行。

图4.6所示为Y维折叠的算法图。

Y维折叠的代价是输入特征图在片外的存储量随$K_{y}$倍增。但由于权重静止数据流下激活值访问规模相对权重小，在ResNet早期层等场景下这一代价可被PE利用率提升所抵消。Y维折叠让硬件保持最简固定阵列，编译器侧承担相位重排与权重布局，无需RTL改动即可完成PE利用率优化。如图4.7所示为Y维折叠（Ky-fold）原理示意图。

##  编译器优化：空间到深度 S2D

针对$stride \geq 2$的卷积层，传统硬件实现会让$stride^{2}$个相位的PE在大部分时间空转。我们在编译器侧提出空间到深度（Space-to-Depth，S2D）优化，将$\left( k_{x}\text{ mod }stride,k_{y}\text{ mod }stride \right)$的$stride^{2}$个相位折到$C_{in}$维，等价转换为$stride = 1$的卷积，提升PE利用率。

S2D的数学等价关系如下。设原卷积参数为$K$、$stride = s$，将输入x与$y$坐标按$(4.5)$式分解：

$$\begin{array}{r}
y = q_{y} \cdot s + r_{y},\ x = q_{x} \cdot s + r_{x},\ \text{其中}\text{ }r_{y},r_{x} \in \lbrack 0,s - 1\rbrack\ 
\end{array}$$

对每个相位$\left( r_{y},r_{x} \right)$，构造重排后的输入特征图：

$$\begin{array}{r}
X_{r_{y},r_{x}}'\left( q_{y},q_{x},c_{i} \right) = X\left( q_{y} \cdot s + r_{y},\, q_{x} \cdot s + r_{x},\, c_{i} \right)
\end{array}$$

将$stride^{2}$个相位沿$C_{in}$维拼接，得到等效输入：

$$\begin{array}{r}
C_{in,new} = s^{2} \cdot C_{in}
\end{array}$$

同时把卷积核按相位重排为

$$\begin{array}{r}
\left\{ \begin{array}{r}
K_{new} = \left\lceil K\text{/}s \right\rceil \\
stride_{new} = 1
\end{array} \right.\ 
\end{array}$$

的等效卷积核。原卷积等价于：

$$\begin{array}{r}
Y\left( q_{y},q_{x},c_{o} \right) = \sum_{k_{y,\text{eff}} = 0}^{K_{\text{new}} - 1}{\sum_{k_{x,\text{eff}} = 0}^{K_{\text{new}} - 1}{\sum_{c_{i,\text{new}} = 0}^{s^{2} \cdot C_{\text{in}} - 1}{X_{r_{y},r_{x}}'\left( q_{y} + k_{y,\text{eff}},q_{x} + k_{x,\text{eff}},c_{i} \right)}}} \cdot W'\left( k_{y,\text{eff}},k_{x,\text{eff}},c_{i,\text{new}},c_{o} \right)\ 
\end{array}$$

S2D的核心性质是输入数据在DDR中只是按相位重排索引，不需要复制------这与Y维折叠的"$y$偏移复制"不同。S2D在编译器侧完成数据重排，硬件视角看到的是$K_{new} \times K_{new}$、$stride = 1$、$C_{in}$加宽至$s^{2} \cdot C_{in}$的普通卷积，MAC阵列在$C_{in}$维充分填充。

S2D的实现完全在编译器侧。

第1步，条件判定：scheduler在编译期判断$stride \geq 2 \land K \geq stride$时自动启用S2D；与Y维折叠判定独立，两者可叠加触发。

第2步，权重与特征图重排：编译器将$stride^{2}$个相位的权重按$C_{in,new}$索引拼接，将输入特征图按相位拼接为$C_{in}$加宽形式，DDR中按重排后的布局摆放。

第3步，生成配置：scheduler用$K_{new}$、$stride = 1$、$C_{in,new}$等效维度算cfg_regs，硬件按等效卷积运行。整个过程无需RTL改动，硬件继续按"普通卷积"运行。

如图4.8所示为S2D编译链实现算法图，图4.9为S2D变换前后图像示意图。

S2D配合大$stride$的首层卷积，如$K = 4$、$stride = 4$效果显著。Y维折叠与S2D亦可由用户通过命令行选项强制启用。

S2D与Y维折叠的联合作用让编译器可以在不改动硬件的前提下，对${ C}_{in}$小、$stride$大的常见低利用率场景给出优化方案，硬件保持固定阵列与简洁的配置接口。

### 4.10 子系统 DMA 与 AXI 接口集成

DMA子系统位于加速核外，对接AXI4主接口，承担片外DDR与片上各缓冲区之间的批量数据搬运。如图4.10所示DMA子系统结构图。

DMA子系统的核心是1个Xilinx AXI DataMover IP，提供MM2S（Memory-Mapped to
Stream）与S2MM（Stream to Memory-Mapped）两条搬运通道。AXI DataMover
IP自身实现AXI4突发协议，对外暴露简化的命令---状态---数据流接口，简化自研控制器的实现。

DMA子系统的控制器分为四类。

第1类是输入特征图DMA控制器，将IFM从DDR经MM2S通道写入IFB。

第2类是权重DMA控制器，将权重从DDR经MM2S通道写入WB。

第3类是输出特征图DMA控制器，将OFM从OFB经S2MM通道写出到DDR。

第4类是残差/偏置DMA控制器，将偏置与残差数据从DDR经MM2S通道写入bias_rf与Shortcut
Bank。

![[]{#_Ref229644114 .anchor}图4.10
DMA子系统结构图](.docx-media/media/image27.png){width="4.462962598425197in"
height="3.451431539807524in"}

DMA 4类控制器的描述符寄存器字段详见附录[表A.5](#_Ref229686948)。

由于AXI DataMover
IP仅有1条MM2S通道，idma_ctrl与wdma_ctrl通过mm2s仲裁器mm2s_arb串行共享。mm2s_arb实现简单的轮转仲裁：每次完成一段burst后切换到对端，避免idma长时段独占导致wdma饥饿。S2MM通道由odma_ctrl独占，无需仲裁。rdma_ctrl在多核扩展层中也参与MM2S通道竞争，由mm2s_arb统一仲裁。

DMA子系统对外仅暴露1个AXI4主接口，由AXI主口聚合器axi_m_mux实现。axi_m_mux把AXI
DataMover的MM2S/S2MM主口与DFE的主口三路聚合后挂到唯一的AXI4主接口。这一组织方式让加速器对外的AXI拓扑与SoC内常见的1主1
Lite结构对齐，简化集成。

AXI-Lite从口由AXI-Lite
CSR模块axi_lite_csr实现。axi_lite_csr暴露4个启动期寄存器：描述符链表基址、链表长度、控制位、start_dfe触发位以及若干状态寄存器给控制核。控制核在系统启动时写一次4个寄存器并触发start_dfe，整段多层卷积的层切换、权重切换、配置切换均由DFE与sequencer自动完成，无需控制核逐层介入。

描述符获取引擎DFE是DMA子系统与sequencer之间的桥梁。DFE在start_dfe拉起后自动从DDR中拉取描述符链表，按描述符类型分发：TYPE_IDMA送入idma_ctrl命令口、TYPE_WDMA送入wdma_ctrl命令口、TYPE_ODMA送入odma_ctrl命令口、TYPE_RDMA送入rdma_ctrl命令口、TYPE_CFG=0x3送入sequencer的cfg写口。描述符FIFO容量为128，可容纳一层完整cfg的全部CFG_WRITE描述符。一层卷积的描述符段顺序为：CFG_WRITE$\times$N
→ IDMA_DESC → WDMA_DESC → RDMA_DESC →
ODMA_DESC，由编译器在描述符链生成阶段确定。

### 4.11 多核 W 切片扩展

为支持更高吞吐与多核扩展，加速器在加速核之上提供多核扩展层multicore。

多核扩展层包含$N$个加速核、基于Xilinx SmartConnect
IP的AXI互连交换、AXI-Lite一对多分发模块。各核之间通过W维切片调度并行，核间不共享数据通路与控制FSM，仅在层边界通过握手寄存器同步。

W切片调度的实现流程分为三步。

第1步，切片分配：编译器按核数$N$把$W_{in}$维分给$N$个核，每核处理一段子图。为保证卷积窗口在核边界处的语义一致性，每核额外保留边界冗余列：当$K = 3$且$stride = 1$时，相邻核之间需要重叠2列输入；边界冗余列采用计算冗余方式实现，不引入跨核同步开销。

第2步，非对称pad：边界核的外侧使用cfg配，内侧使用0
pad；这一非对称pad由cfg_regs在多核场景下分别配置。

第3步，层边界握手：每核完成一层后拉起完成标志位，多核扩展层在所有核done_sticky拉起后才允许下一层启动。

跨核SRAM直送是多核扩展层的核心优化。生产者核的odma_ctrl在写出本层OFM时，目标地址不是DDR而是消费者核的IFB物理地址。消费者核的IFB通过ifb_axi_slave模块挂载在AXI互连上，可从外部接收写入，将数据直接写入IFB
ring。这一方式避免了上一层OFM写DDR、下一层IFM再从DDR读的双向带宽消耗，使多核加速比不被DDR带宽过早限制。如图4.11所示多核扩展层结构图，图4.12为跨核SRAM直送机制的示意图。

多核W切片场景下,一行IFM散布在多个内存。IDMA/ODMA dispatcher把一条
IDMA_DESC内部拆为多条突发段命令（Scatter-Gather command,
SG），每条对应一个内存内的AXI
burst段。突发段命令列表的字段映射详见附录[表A.1](#_Ref229686689)。

多核扩展层在代码组织上保持单核RTL不变，扩展通过外层完成：仅多核扩展层与编译器侧在不同$N$之间切换。增加新核数仅需扩展多核扩展层的外壳与AXI互连配置，不需要改单核RTL。[多核扩展层目前已在]{.mark}$N = 1\text{/}2\text{/}4$[三种配置下完成综合]{.mark}。

### 4.12 DSP 块跨列复用映射方案

MAC阵列模块在输入通道广播数据流下，每周期同一拍16-$C_{in}$激活值向量同时被16列消费、各列权重独立，相邻列在物理实现层面共享同一拍激活向量、仅权重不同。据此结构性特征，可把MAC阵列中相邻两列的INT8乘法器合并映射到一个DSP48E1块上，使整个$16 \times 16$阵列的256个乘法器从查找表实现迁移至DSP块实现。该方案在保持数据通路对外接口与位级行为完全等价的前提下，由综合阶段在两种映射之间作选择。如图4.13所示DSP块跨列复用映射方案原理图。

![[]{#_Ref229646413 .anchor}图4.13
DSP块跨列复用映射方案原理图](.docx-media/media/image30.png){width="5.8189304461942255in"
height="2.2037029746281713in"}

DSP48E1块内部提供一个25 bit×18 bit有符号乘法器，其乘积位宽为43
bit。映射规则将相邻两列的两个8 bit权重$w_{0}$、$w_{1}$打包到25 bit
A端：低8 bit放${ w}_{0}$、中间9 bit置零作为进位隔离位、高8
bit放$w_{1}$，可写为$A = \text{\{}w_{1},9'\text{b}0,w_{0}\text{\}}$；将该行激活值$act$符号扩展为18
bit B端。一次乘法的43
bit乘积$P = A \times B$同时承载两路独立INT8乘积：低16位经位提取后作符号校正得$w_{0} \times act$的有符号结果，高位段经位提取后同样作符号校正得$w_{1} \times act$的有符号结果。9
bit进位隔离位保证了两路乘积在43
bit宽度内不会跨段串扰。符号校正逻辑承担将无符号视图与有符号视图之间的偏置项扣除，按$w_{0}$、$w_{1}$的符号位与$act$拼出常数补偿项即可，整段以查找表组合电路实现，不再调用乘法器资源。

按上述映射规则展开至阵列层，$16 \times 16$阵列以$8 \times 16$行的方式重组：每行的相邻两列共用同一DSP48E1块，行间结构独立。单核MAC阵列的乘法器从原查找表实现的256个INT8乘法器折合为$8 \times 16 = 128$个DSP48E1块，$N = 4$配置下整个加速器的MAC阵列共占用$4 \times 128 = 512$个DSP块；上游接行缓存模块的窗口口、侧路接权重缓存模块的权重口、下游接部分和累加模块的部分和口三组接口的位宽、握手协议、循环边界与原查找表实现完全一致，加法树结构、PSUM位宽以及流水节拍亦保持不变。综合阶段可在两种映射之间选择走查找表实现还是DSP块实现。

将MAC阵列乘法器从查找表实现迁移至DSP块实现，可使加速器整体的查找表占用显著下降、DSP资源利用率明显提高；与此同时，由于DSP块内乘法器为硬连线结构、其传播延迟短于查找表搭建的多级乘法树，关键路径的时序裕度也相应改善。

##  本章小结

本章按模块顺序给出了FLUX_CNN加速器的具体实现。加速核内的5个数据通路模块依次承担窗口生成、乘加计算、部分和累加、量化后处理与权重供给五项职责：行缓存模块组织IFM行流，按6层FSM节拍向ARF发射激活值像素向量，$K \times K$窗口组装由下游MAC阵列在ARF内按$k_{x}/iss_{pos}$偏移完成；前向压力发射策略支持任意$H \times W$输入；MAC阵列模块由$16 \times 16$PE共256个INT8乘加单元组成，采用输入通道广播+权重静止+激活值滑窗行复用+输出部分和累加四层复合数据流；部分和累加模块以16列独立SRAM实现PARF累加，每列共享写地址写使能；SDP后处理模块在ofb_writer内实现"偏置
→ 移位 → 饱和 → 残差 → 饱和 →
OFB"INT8后处理链；权重缓存模块以WB、WRF双层结构供给权重。控制路径上，cfg_regs双写口设计与sequencer
6层FSM协同完成单层调度：50余个cfg寄存器完整描述一层卷积，控制核仅写4个启动寄存器，描述符流由DFE自动消费。在此基础上，编译器侧的Ky-fold与S2D两项PE利用率优化方案分别针对$C_{in} < 16$与$stride \geq 2$两类低利用率场景，将形状适配压力从硬件迁移至编译器，使硬件得以保持最简固定阵列。

DMA子系统承担片外数据搬运，对外仅暴露1个AXI4主接口与1个AXI-Lite从接口；多核W切片扩展层在不改动单核RTL的前提下完成核数扩展。此外，本章给出了$16 \times 16$INT8
MAC阵列在DSP48E1块上的两种可选映射方案，为综合阶段在查找表与DSP块之间作权衡保留了入口。

阶段二：FPGA功能验证平台。选用VD100开发板，芯片为AMD Versal AI

User
Interface，GUI），实时展示推理结果与端到端延迟。该平台用于验证加速器在真实SoC集成环境下的功能正确性与吞吐。

阶段三：ASIC 版图估算平台。基于开源 ASIC 设计流程 OpenLane2 对单核 `core_top` 在 Skywater 130 nm 工艺下完成版图实现至 post-CTS 阶段，并按工艺缩放公式^[44]^折算至 45 nm 节点，给出版图面积与综合功耗估计，作为同 RTL 在专用集成电路工艺下的指标参考。

###  验证方法

为确保加速器功能正确性与性能达标，验证从功能、性能与对比三个维度展开。

（1） 功能验证

功能验证以PyTorch逐层模拟为参考，以ModelSim仿真输出为被验证对象，逐元素按位比较。验证粒度由细到粗依次为单算子、多层链与整网三个层次：单算子用例覆盖单层卷积；多层链用例覆盖残差融合多层组合；整网用例覆盖ResNet11完整11层。对每一组测试激励，编译器生成完整的DDR数据镜像与描述符链表，仿真平台从DDR模型中取数运行，最终将OFB区中的输出特征图与PyTorch端的参考结果做逐字节比较。当且仅当全部输出字节完全一致时判定为PASS。

（2） 性能验证

性能验证关注三类指标：

第一类为综合时序，由Vivado在不同时钟频率约束下报告最差负余量WNS，由此推断最大可达频率Fmax；

第二类为资源占用，由Vivado资源报告统计LUT、FF、BRAM、DSP四类资源在不同配置下的使用量；

第三类为功耗，由Vivado功耗分析工具估计在指定时钟频率与典型激励下的[片上动态与静态功耗]{.mark}。

（3） 对比验证

对比验证将FLUX_CNN与已有CNN加速器的实测指标按峰值算力、能效比、时延、资源利用率四个维度进行对照。对照对象分两组：ASIC加速器组包含DianNao、TPU
v1、Eyeriss、Eyeriss
v2与Gemmini；FPGA加速器组包含NVDLA、VTA以及Peng等人的全栈加速器。对照指标在不同工艺与频率下进行折算，以减弱平台差异对结论的影响。

##  性能分析

性能分析关注五个层次的指标：

第一，端到端推理时延与帧率，反映加速器在完整网络上的整体吞吐能力；

第二，MAC阵列利用率，反映硬件计算资源的有效使用程度；

第三，多核扩展加速比，反映多核扩展层在不同核数下的加速能力；

第四，调度策略量化分析，定位整网周期数中各调度因素的贡献；

第五，参数敏感度分析，对${ C}_{\text{in}}$、$K$、$\text{stride}$、$N$、$W$逐参数扫描，量化PE利用率与整网周期数随参数变化的趋势及编译器侧优化的最大收益区间。

###  端到端延迟与帧率

以ResNet11完整11层网络为载体测试端到端推理时延。ResNet11单帧浮点MAC量约为$131 M MAC$。整网端到端推理延迟$T_{e2e}$由整网周期数$N_{cycle}$与系统时钟频率$F_{\max}$决定，对应单帧帧率FPS为：

$$\begin{array}{r}
T_{e2e} = \frac{N_{cycle}}{F_{\max}},\ \ \text{FPS} = \frac{1}{T_{e2e}} = \frac{F_{\max}}{N_{cycle}}
\end{array}$$

其中$N_{cycle}$由仿真平台从首拍IDMA命令发出至ODMA写完最后一字节OFM期间累计周期数采集得到，包含输入特征图搬运、卷积计算、跨层握手与输出写回四部分开销；$F_{\max}$由Vivado时序报告给出。

第二类为多核扩展。$N = 4$ 含 W 切片且不启用跨核 SRAM 直送时，整网周期数为 354,555。引入跨核 SRAM 直送写入路径与 NUMA 跨核数据布局后，上一层 OFM 写片外 DDR、下一层 IFM 再读片外 DDR 的双向带宽消耗被消除，整网周期数进一步降至 201,386，相对 $N = 1$ 含 SDP 基线加速 $2.96 \times$。

第三类为编译器侧调度优化。针对降采样层观察到的访存受限特征，将IDMA行命令按步长行间隔分离，使该类层的IDMA数据量减半；同时将各核IDMA命令行内段顺序由"远端边界段优先"改为"本地段优先"，缓解共享互连中等待开销。两类调度策略叠加后整网周期数由354,555进一步降至173,432，相对未优化基线累计加速 $6.43 \times$，按 135.86 MHz 推荐工作频率折算单帧延迟 1.28 ms、帧率 783 fps。

与 §1.1 表 1.1 端侧实时基线对照，4 核 SMC 配置在 ResNet-11 整网上达到 783 fps，相对 qHD 视频流 30 fps 实时基线约 $26.1 \times$。这一余量为更高分辨率扩展如 1080p 或 4K 视频流预留了充分的时序与算力空间，证实 FLUX\_CNN 在高分辨率单 batch 端侧场景下能够稳定满足实时推理目标。

###  乘加阵列单元利用率

衡量MAC阵列计算资源使用程度有两种统计方式。

第一类是PE利用率，定义为整网累计运算数与MAC阵列峰值运算数的比值，即

$$\begin{array}{r}
\text{PE}\text{利用率} = \text{整网}\text{MAC}\text{量} \times 2\text{/}\left( \text{Fmax} \times \text{阵列宽度} \times \text{整网周期数} \right)
\end{array}$$

反映从端到端视角看每周期每PE的有效计算占比。

第二类是流水占空比，定义为零阶汇合点，即line_buffer输出端的有效与就绪信号同时为高的周期占整网周期数的比例，反映流水线在墙钟时间内不被反压的比例。

如表5.3所示$N = 4$下两种DDR配置下的流水占空比对比，其中4-DDR数据为原理验证仿真结果。

| **DDR 配置** | **整网周期数** | **流水占空比** | **每路 DDR 占空比** |
| :---: | ---: | ---: | ---: |
| **1-DDR** | 313,330 | 41.0% | 84.7% |
| **4-DDR** | 210,290 | 61.0% | 29~44% |
| **4-DDR 多核** | 173,432 | 71.9% | 40~44% |

*表5.3 核数 4 配置下 1-DDR 与 4-DDR 流水占空比对比（按新 RTL 实测 173,432 周期等比缩放）*

由表 5.3 可见，$N = 4$ 配置在 1-DDR 下流水占空比仅 41.0%，单路 DDR 占空比已达 84.7%，说明在 4 核场景下片外 DDR 带宽是限制流水占空比的主要瓶颈。当将 DDR 路数扩展为 4 时，流水占空比提升至 61.0%，每路 DDR 占空比降至 29% 至 44%；进一步开启编译器侧强制多核切片后，流水占空比可达 71.9%，整网周期数进一步降至 173,432 周期。该结果表明，片外存储通道带宽是影响多核加速比偏离线性的主要因素之一。实际系统中片外存储配置由部署目标决定，本论文以多核加速器对片外存储带宽的依赖关系作为定性结论，不依赖具体通道数选择。

进一步分层考察$N = 4$下的每层PE利用率分布。$K = 3$主路径层共5层，PE利用率位于78%
至93%
区间，其中$K = 3$、$stride = 1$、${ C}_{in} = C_{out} = 16$层利用率最高达92.7%；降采样层$K = 1$且$stride > 1$共3层，PE利用率显著偏低，分别为18.7%、16.1%、40.4%；Patch层在空间到深度变换后PE利用率为70.9%；FC层因输出通道维仅有144触发数，PE利用率约5%。整网累计PE利用率约为70.9%。

$K = 1$、$stride > 1$的降采样层的低利用率不是计算资源不足，而是访存数据量与计算触发数失配。该类层访存量与$K = 3$层相近，但每空间位置仅触发1次乘加而非9次，计算触发数仅为$K = 3$层的1/9。针对该特征，编译器把IDMA行命令按stride行间隔分离，使该类层IDMA数据量减半，整网周期数从204,240降至190,977，单层周期数减少约40%。

编译器侧的Y维折叠与空间到深度两项优化对低利用率层的提升尤为显著。以ResNet11
Patch层为例，原始形状$K = 4$、$stride = 4$、$C_{in} = 4$在$16 \times 16$阵列上仅占用4/16行PE，未启用空间到深度时该层整网周期数为654,404周期；启用空间到深度后该层等效转换为$K = 1$、$stride = 1$、$C_{in} = 4$标准卷积，PE行被填满，整网周期数降至129,594周期，单层加速$5.05 \times$。

###  多核扩展加速比

从表 5.2 可读出 $N = 1$ 至 $N = 4$ 三种核数下的整网加速比。在含空间到深度优化的基础上，$N = 2$ 相对 $N = 1$ 加速 $1.32 \times$；$N = 4$ 相对 $N = 1$ 在三种配置下分别加速 $1.68 \times$（仅 W 切片）、$2.96 \times$（加跨核 SRAM 直送）、$3.44 \times$（加编译器调度优化全开）。$N = 2$的加速比$1.32 \times$，偏离理想$2.0 \times$的原因有二：第一，跨核边界引入的额外计算使每核计算量略多于$1\text{/}N$；第二，层边界握手与AXI互连仲裁开销在小用例下不可忽略。$N = 4$在1-DDR含W切片配置下加速$1.68 \times$进一步偏离线性，主要原因为DDR带宽限制。

在多核W切片机制下，FLUX_CNN能够在不改动单核RTL的前提下扩展到$N = 2$与$N = 4$配置，并通过跨核SRAM直送写入路径避免上一层OFM写片外DDR、下一层IFM再读片外DDR的双向带宽消耗。多核加速比的实际上限由片外DDR带宽决定。

###  调度策略量化分析

为定量分析整网周期数中各调度因素的贡献，调度策略量化分析采用控制变量法：将SmartConnect互连IP、偏置寄存器堆、对外存请求通道的仲裁器以及命令调度引擎中的子状态分别替换为零延迟理想模型，比较替换前后的整网周期数差异，从而量化哪个组件在拖慢吞吐。

互连IP开销方面，SmartConnect互连IP的寄存器流水级累计占整网周期数的7.0%，约14,354周期。其中访存受限层，如降采样层与Patch层的开销占比为12%
至13%，计算受限层，如$K = 3$主路径层的开销占比为0.5%
至1.3%。互连开销在不同层之间呈双峰分布，与各层PE利用率的高低分组对应。

偏置寄存器堆方面，将偏置就绪信号替换为永远有效后，整网周期数仅减少132个周期，占整网周期数的0.06%，表明偏置寄存器堆的切片切换等待开销可忽略。

命令调度引擎的时间分布方面，将其内部状态机各子状态的占用周期数累计后，取指、就绪等待、命令发射、数据传输与完成确认的占用比分别为17.5%、12.6%、1.0%、44.7%
与0.0%，剩余24.2%
为层间空闲。该分布表明命令排队等待时间已较短，进一步压缩取指等待路径的优化潜力上界约为2%
至3%。

综合上述结果，当前进一步优化空间为：移除SmartConnect流水级最多再缩短7.0%，进一步压缩命令等待最多再缩短约3%；剩余约30%
利用率间隙主要来自硬件计算与访存的固有同步开销，需要从MAC阵列流水深度与降采样层访存模式两方面继续展开。

###  多网络ASIC工艺折算性能

将ResNet11之外的代表性CNN网络置于FLUX_CNN的分析模型中估计端到端延时与帧率，以刻画加速器在更广泛工作负载下的吞吐分布。

单网整网周期数按层级 PE 利用率加权后的分析模型折算：

$$N_{cycle} = \frac{N_{MAC}}{N_{cores} \times N_{PE} \times \eta_{PE}}$$

其中 $N_{MAC}$ 为整网累计 MAC 量，$N_{cores} = 4$ 为多核数，$N_{PE} = 256$ 为单核 MAC 阵列规模，$\eta_{PE}$ 为各网络按层级 PE 利用率加权后的平均利用率。层级 PE 利用率取自 §5.7.2 节实测分类：$K = 3$ stride=1 与 stride=2 主路径取 85%，$K = 1$ stride=2 降采样取 20%，$K = 5$ 与 $K = 7$ 大核取 95%，Patch S2D 取 71%，深度可分卷积取 6%（PE 行仅利用 1/16），全连接取 5%。

ASIC 目标频率取 850 MHz，4 核峰值算力为：

$$P_{peak}^{ASIC} = N_{cores} \times N_{PE} \times F_{max}^{ASIC} \times 2\,\text{ops/MAC} = 1024 \times 850\,\text{MHz} \times 2 = 1{,}740.8\,\text{GOP/s}$$

FPGA 参考频率取 §5.4.2 推荐工作频率 135.86 MHz，4 核峰值算力为：

$$P_{peak}^{FPGA} = 1024 \times 135.86\,\text{MHz} \times 2 = 278.2\,\text{GOP/s}$$

##  与已有工作对比

将FLUX_CNN的实测指标与代表性CNN加速器的实测数据进行横向对比。

FLUX_CNN的目标场景为端侧推理。$16 \times 16$单核阵列规模与Eyeriss、Gemmini同量级，为后续ASIC工艺迁移留有空间；在当前FPGA验证平台上，DSP实现方案已使16×16阵列的INT8乘法器全部从查找表迁移至DSP块，DSP48E1占器件99.0%，DSP资源利用率不再是性能短板。

在功能维度，FLUX_CNN的实测结果可归纳为四点。

第一，编译器侧Y维折叠与空间到深度两项PE利用率优化方案在$C_{\text{in}}$较小或步长较大时大幅缩减整网周期数：ResNet11
Patch单层从654,404周期降至129,594周期，整网从约1,115K降至596K，硬件保持固定$16 \times 16$阵列。

第二，行级流式环形缓冲让单核硬件可以处理任意$H \times W$输入，无需为不同输入尺寸重新综合。

第三，多核W切片配合跨核SRAM直送写入路径在ResNet11$N = 4$上实现3.44×
加速，并通过1-DDR与4-DDR对照定量给出DDR带宽对加速比的限制。

第四，DSP48E1 块跨列复用映射方案在保持 $N = 4$ 整网仿真按位一致的前提下，将查找表占器件比例压低至 46.0%、DSP48E1 占器件比例提升至 99.0%，布局布线后推荐工作频率达 135.86 MHz、片上功耗 1.925 W。

##  本章小结

本章对FLUX_CNN加速器进行了功能、性能与对比三方面的实验验证。

功能层面，三套测试集与ResNet11整网仿真共同覆盖加速器的功能验证范围。

性能层面，$N = 4$ SMC 配置在 Kintex-7 XC7K325T 布局布线后占用 LUT 93,756（46.0%）、FF 60,925（14.9%）、RAMB36 288（64.7%）、DSP48E1 832（99.0%），推荐工作频率 135.86 MHz、片上功耗 1.925 W、峰值算力 278.2 GOP/s、峰值能效 144.5 GOP/W。ResNet-11 整网在 $N = 4$ 主配置下整网周期数 173,432，单帧延迟 1.28 ms、帧率 783 fps，相对 30 fps 实时基线约 $26.1 \times$。对各调度因素的量化分析进一步给出整网周期数中互连 IP 开销 7.0%、偏置寄存器堆开销 0.06%、命令调度引擎可压缩潜力 2% 至 3%。

对比层面，FLUX_CNN $N = 4$ 配置在 Kintex-7 FPGA 上峰值算力 278.2 GOP/s（135.86 MHz）、ASIC 850 MHz 折算峰值算力 1,740.8 GOP/s，$16 \times 16$ 单核阵列规模与 Eyeriss、Gemmini 同量级。FLUX_CNN 通过编译器侧 PE 利用率优化、行级流式缓冲与跨核 SRAM 直送、DSP48E1 块跨列复用映射三类机制覆盖端侧典型网络的形状空间与 FPGA 平台的资源利用上限。

#  结论 {#结论 .标题-居中}

本论文围绕端侧流式计算场景下的卷积神经网络硬件加速需求，以分层调度为核心思路设计并实现了一款INT8卷积加速器FLUX_CNN，构建了从硬件架构、寄存器传输级实现到软件工具链与三阶段验证的完整体系。硬件侧采用核内寄存器配置加核间任务描述符链表的双层调度方案，核内由配置寄存器驱动6层有限状态机完成单层全部循环嵌套展开，核间通过任务描述符接口协调多核多层协作；数据通路以$16 \times 16$ INT8 MAC阵列与三级寄存器堆为基础，建立输入通道广播、权重静止、激活值滑窗行复用与输出部分和累加四层数据复用策略，配合零乘除法的硬件地址生成、行级流式环形缓冲与权重轮次分块，使单核硬件可在不重新综合的前提下处理任意$K \times K$卷积核、任意步长、任意$C_{in}/C_{out}$切片以及任意$H \times W$输入；加速核内置残差通路，shortcut分支在输出特征缓冲内原地累加，避免中间结果落回片外DDR。软件侧构建覆盖前端PyTorch模型解析与量化、中端图级调度与层间融合、后端代码生成与任务描述符编排的端到端编译器工具链，并针对$C_{in} < 16$与$stride \geq 2$两类低PE利用率层提出Y维折叠与空间到深度两项编译器侧重映射方法，在硬件保持固定阵列的前提下填满PE。多核扩展层采用W维切片调度与跨核SRAM直送写入路径，在不改动单核RTL的前提下提供$N = 1, 2, 4$多核配置，使上一层OFM直接写入下一层IFB而避免片外DDR往返。

实测数据方面，FPGA 综合阶段在 Kintex-7 XC7K325T 平台对 $N = 4$ SMC INT8 SIMD 配置完成布局布线，占用 LUT 93,756（46.0%）、FF 60,925（14.9%）、RAMB36 288（64.7%）、DSP48E1 832（99.0%），推荐工作频率 135.86 MHz、片上功耗 1.925 W、峰值算力 278.2 GOP/s、峰值能效 144.5 GOP/W。ResNet-11 整网在 4 核主配置下整网周期数 173,432，对应单帧延迟 1.28 ms、帧率 783 fps，相对单核含空间到深度基线累计加速 $3.44 \times$、相对 30 fps 实时基线约 $26.1 \times$；通过 1-DDR 与 4-DDR 对照量化片外存储带宽对多核加速比的限制。SoC 集成测试阶段在 VD100 开发板（Versal AI Edge XCVE2302）上完成三核加速器的实际烧录与上位机 Demo GUI 演示，板级输出与 ModelSim 仿真及 PyTorch 浮点参考逐字节一致。ASIC 版图估算阶段基于 OpenLane2 在 Skywater 130 nm 工艺下完成单核 `core_top` 版图实现至 post-CTS 阶段，实测单核总单元面积 31.96 mm²（含 96 块 SRAM 宏 27.32 mm²、标准单元 4.65 mm²）、功耗 1.045 W；按 Stillmaker 与 Baas[44] 工艺缩放公式折算至 45 nm 节点，单核单元面积 3.84 mm²、功耗 0.136 W，4 核估计 15.4 mm² / 0.54 W，850 MHz 下峰值算力 1.74 TOP/s、峰值能效 3.2 TOP/W，相对 FPGA 实测能效 144.5 GOP/W 提升约 22 倍，体现 ASIC 专用工艺相对 FPGA 的能效优势。控制变量法量化各调度因素对整网周期数的贡献，识别出 SmartConnect IP 寄存器流水级累计占 7.0%、命令调度引擎取指与等待开销可压缩约 2~3%、偏置寄存器堆切换开销小于 0.06%，为后续优化提供基于实测的分项收益参考。

未来工作可分两个方向继续推进。算子覆盖与编译器栈方面，当前工具链以Conv2D为核心算子，需要将Depthwise Convolution、Pointwise Convolution、Residual Add、Concat等算子纳入正式支持范围，并在编译器侧引入图级层间融合与跨核任务切分的代价模型，使任务描述符流的生成从手工配置转向自动化调度；模型量化可探索INT4与混合位宽量化感知训练相结合的路径，进一步压缩权重存储与片外带宽消耗；端到端验证集中于ResNet-11风格的中等规模模型，需将MobileNet、YOLOv5n、轻量级目标检测网络等典型端侧模型纳入回归测试。架构演进方面，本论文已基于OpenLane2完成45 nm版图估算，下一步可在更先进工艺节点上完成ASIC后端实现与流片以给出可直接对照的面积、功耗、能效数据；同时可探索将稀疏加速、跨层融合、动态精度切换等机制引入分层调度框架——稀疏加速可在PARF累加路径上引入跳零机制以降低剪枝后冗余计算的能耗，跨层融合可借助行级流式环形缓冲扩展为跨层环形缓冲将相邻卷积层OFM直接送入下一层行缓存，动态精度切换则可在同一MAC阵列上支持INT8与INT4混合位宽以适配不同算子的精度需求。本论文为端侧流式CNN加速器提供了一套覆盖硬件架构、编译器工具链与多阶段验证的自洽实现与验证框架，未来需持续推进硬件、编译器与算法三者的协同设计。

#  修改记录 {#修改记录 .标题-居中}

四、毕业论文内容重要修改记录

**指导教师要求的重大修改：**

1. 关于摘要部分。指导教师指出原摘要中 DSP 跨列复用映射方案的篇幅过重，未能充分体现端到端软件编译链工具链的设计工作，也缺失对加速器残差通路设计的描述。据此对摘要进行了重写，删除原 DSP 长句，新增残差通路（shortcut 分支在输出特征缓冲内原地累加）与端到端编译器工具链（覆盖前端 PyTorch 模型解析与量化、中端图级调度与层间融合、后端代码生成与任务描述符编排）的相关描述，并将整体字数控制在 500 字以内。

2. 关于第 1 章研究背景与意义。指导教师指出原章节在动机叙述上偏重"任意 $K$、可变步长、多分支残差等结构通用化"等通用层面问题，与本论文"qHD/1080p 单批次实时"的核心场景主线不够紧密。据此重写研究动机段，将核心问题聚焦为高清单批次推理利用率低与延迟抖动大两个具体痛点，并据此组织 1.1 节叙述脉络。

3. 关于第 1.2.1 节端侧加速器架构研究进展。评阅意见指出原章节按时间顺序罗列 DianNao、TPU、Eyeriss、NVDLA、Gemmini 等代表性工作的性能指标，呈现综述式结构但未明确归纳现有工作在 1080p 单批次场景下的共性不足。据此在 1.2.1 节末尾新增批判性总结段，对上述工作面向端侧高分辨率单批次场景时的局限进行归纳，使文献综述与本论文动机形成对照。

4. 关于第 1.2.2 节软硬协同调度研究进展。指导教师指出原章节对 VTA、Fused-Layer、MAERI、Simba 等代表性工作仅做综述式介绍，未将各工作在端侧场景下的具体痛点显式挑出。据此对该节进行修订，每条文献引用后补充一句"该工作在端侧高分辨率单批次场景下的不足之处"，使文献综述紧扣本论文研究动机。

5. 关于第 1.3 节研究内容与结论部分的核心创新结构。指导教师指出原"4+1"创新结构中将 DSP48E1 跨列复用映射方案与其他四项核心创新并列，但该方案属于 FPGA 验证平台上的工程实现配套，与本论文"高清实时端侧推理"主线关联较弱，作为核心创新偏弱。据此将 DSP 跨列复用降级为工程实现配套描述，核心创新压缩为四项（核内寄存器配置加核间描述符链表的双层调度、单批次高分辨率行级流式加多核 W 维切片调度、多维度数据复用加编译器侧 PE 利用率重映射、端到端编译器工具链），§1.3 与结论叙述同步调整。

6. 关于第 5.7.1 节端到端延迟与帧率。评阅意见指出表 5.3 给出了不同核数与编译模式下的整网周期数与帧率数据但缺少直观的对照图。据此补充"核数 × 编译模式 × 帧率"柱图与加速比折线图（图 5.2），与表 5.3 形成数据图表对照。

7. 关于第 5.7.6 节数据复用效果分析。评阅意见指出该节仅以表格形式给出 ablation 实测数据，缺少数据流复用机制的理论分析与对比示意图。据此在 §3.6.1 中新增"五级存储层级与能耗梯度"示意图作为理论分析基础，在 §5.7.6 中新增"逐项加入复用机制后的能耗递减"条形图，形成"理论模型 + 实测数据"的双重佐证。

8. 关于全文术语一致性。指导教师指出全文多处英文术语如 Edge、Streaming、batch、MAC、Processing Element 等存在中英文混排不一致的情况。据此对全文术语进行统一整理，每个英文术语首次出现给出完整的中文与英文对照，后续统一采用中文写法。
